# Plateway GUI workflow sequences

Generated by `node apps/plateway/evidence/tools/gui.cjs` (do not edit by hand). Each step was performed with real controls in Chromium on the shared Web Host. After each step the script checked the App's persisted state through a separate Infra MCP client on the same run against the expected result, then froze the step: it waited until no call the step made was outstanding, read the App's state and version, and stopped if the version had changed since before the check. The observations, version and virtual time below come from that frozen state; the script then scrolled the outcome into view, checked that it is fully on screen and reads as expected, and only then took the screenshot. A failed expectation stops the script, so every step below is observed as expected. Every MCP call made in a step is listed with its arguments and result. Every call is owned when it is sent, by the step open at that moment: page reads and tool discovery, the page's own writes and previews (`POST /api/call`), forced calls from the page's business session, second Agent reads and writes, Infra events, clock moves, the seed load and the inspector's own snapshot reads. A step opens when the previous one is sealed or its sequence begins, and its action runs inside it; the page load before the first sequence and the two pieces of work between sequences have owners of their own (the two are listed in `run.json` as `between_sequences`). A call sent with no owner stops the script, and a reply never changes ownership. A call sent after a step is frozen stops the script and cannot count toward a submitting step, which must list a write or forced call. Each call has exactly one terminal outcome (the reply, or a failure with its HTTP status and error); a failure or a second outcome stops the script. A forced call carries a header token bound to the exact tool and arguments it was issued for. Recorder errors are append-only, so a stop that a caller catches is still reported at teardown. Page writes and previews are listed with the raw arguments (tokens and versions included, unshortened) and the raw reply (HTTP status and JSON body, including fee breakdowns and tokens). Writes by a second Agent MCP client, Infra events, clock moves and forced calls are listed raw, except that the host wall-clock fields `received_at` and `processed_at` in Infra event receipts are replaced by a note so that repeated captures are identical (their virtual times are kept); reads by the second Agent client are summarized to the fields the step checks; page reads, tool discovery and inspector reads are owned and waited for but not listed. Before capturing, the script runs the 20 recorder probes in `evidence/tools/probes.cjs`; each must make the recorder stop with its exact expected message, and the results are in `run.json` (`recorder_probes`). The capture runs Chromium with software rasterization on one thread and replaces the page's random request IDs with a counter, so two runs on the same machine give the same screenshots and step data; on another machine or Chromium build, anti-aliased edges can differ by a few pixels.
