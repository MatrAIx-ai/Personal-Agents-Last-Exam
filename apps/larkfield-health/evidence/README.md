## Workflow sequences, state and tests

[gui/README.md](gui/README.md) lists 14 sequences, 93 steps, on two runs (the second loads policies that drop tools). The steps are those of `tests/web.browser.cjs`, run unchanged inside the recorder ([tools/recorder.cjs](tools/recorder.cjs)), plus 3 evidence-only sequences for the read-only claim, explanation-of-benefits and plan views; 178 checks passed (175 of them the browser acceptance's own): 176 are listed with their steps and 2 are run-level checks of `tests/web/harness.cjs` over each whole run, listed in [gui/README.md](gui/README.md#run-level-checks) and `run.json` (`run_level_checks`). For every step the table records the action, the expected result, the element the step checks (outlined in orange in the screenshot), every record that changed since the previous step, read through a separate Infra MCP client from the frozen state (the 3 steps of the evidence-only sequences also record their own reading of the App), the MCP calls the recorder lists for the step, the version, the virtual time and the checks passed. The recorder rules: every call, in every tab of the browser context, is owned by the step open when it is sent; a step is frozen before anything is taken from it and stops the script if the version moved between its check and its freeze; each call has exactly one terminal outcome; a failure stops the script unless the test induced it (a drop the step declared beforehand, or a request a route of the test aborted, listed with its cause and `reached_host`); a forced call carries a token bound to its exact tool and arguments; and recorder errors are append-only. Before capturing, `gui.cjs` runs the 28 recorder probes in [tools/probes.cjs](tools/probes.cjs), each on a fresh page.

## Regenerate

From the repository root, after `npm ci` and `npx playwright install chromium`:

```sh
node apps/larkfield-health/evidence/tools/regenerate.cjs   # gui/, mail/ and this index, then the App load digest; add --captured-on YYYY-MM-DD to keep a recorded capture date
node apps/larkfield-health/evidence/tools/reference.cjs    # reference/ (needs the reference product's public pages and cdnjs)
```

`regenerate.cjs` runs `tools/gui.cjs` (which first runs the recorder probes), `tools/mail.cjs` (which also runs `tests/mail.integration.cjs`), `tools/index.cjs` and `tools/digest.cjs` in that order and stops at the first failure. `gui.cjs`, `mail.cjs` and `reference.cjs` write their captures to a temporary folder and replace the committed files only after the whole run has passed. The capture tools launch Chromium with software rasterization on one thread (`--disable-gpu --num-raster-threads=1 --disable-partial-raster`), take screenshots with animations disabled and replace the page's random request IDs with a counter, so two consecutive runs of `gui.cjs` and of `mail.cjs` on the same machine gave byte-identical files; on another machine or Chromium build, anti-aliased edges can differ by a few pixels. The reference screenshots depend on the reference product's pages and documents still answering as they did: `reference.cjs` refuses a capture whose rendering mode, scale or size differs from the committed manifest and replaces nothing unless run with `--update`, keeps an entry's `captured_at` while its bytes are unchanged, and `node apps/larkfield-health/evidence/tools/reference.cjs --self-check` exercises these rules offline with stubbed captures of the committed files.
