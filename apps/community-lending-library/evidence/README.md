## Ordered implemented captures and assertions

Rerun [tests/browser.cjs](../tests/browser.cjs) with `PALE_LENDING_SCREEN_DIR` to regenerate the captures below and `steps.json`. Captures use Chromium Headless Shell 156.0.8078.79, Playwright 1.56.1, a 1280 × 850 viewport, sandbox profile and eight named synthetic runs on Core. Browsing and decisions use the same App Agent tools as direct MCP. A distinct Infra MCP client checks persisted data/version; a second Agent client verifies user-scoped results.

| Run / stage | Start → control → result | Observed / Core readback |
| --- | --- | --- |
| `lending-review-normal`, 01–04 | Catalog → exact word search → item C1 → preview → discard | Eight cards initially, search leaves one; hold preview renders without a write. Discard leaves full business data and version unchanged. |
| Same, 05–08 | Preview → confirm C1 → try third copy C2 → Holds → reload | C1 is written once; third copy errors inline with no version/custody change. Frame 06b verifies that a member who already holds Magnifying glass is not offered another queue entry. Names, labels and dates survive page reload. |
| Same, 09–11 | Request H1 checkout → wait → external desk rejects attempt 2 → retry/accept attempt 3 | Pending means no loan. Rejection is visible and hold/loan arrays unchanged. Accepted replacement opens one L2, independently read by Agent. |
| Same, 12–16 | Preview → confirm L2 renewal → request return → accept → read receipts | Preview does not mutate; confirm adds three days. Return remains pending until desk acceptance closes L2, with checkout and return receipt IDs visibly linked to the item. |
| `lending-review-stale`, 17–19 | Preview renewal → Infra joins queue → confirm old preview → refresh/preview | Stale confirmation denied inline with identical version and business state after denial. Re-opened preview explains the waitlist and shows no confirm button; earlier due date unchanged. |
| `lending-review-overdue`, 20–22 | Inspect overdue L1 → preview renewal → inspect maintenance C9 → try available C1 | No renewal, maintenance copy has no hold control, and active overdue loan blocks another hold with unchanged version and custody. |
| `lending-review-waitlist`, 23–25 | Filter unavailable → open I2 → join → inspect position → leave | Private queue position matches Agent; after leaving, Agent sees an empty queue and Core retains one closed queue-history record without exposing another member. |

| `lending-review-evaluation`, 26 | Load full evaluation history → Current loans | Active and returned loans are separate, sorted by checkout date (newest first), and agree with a separate Agent readback; all affected buttons and ID text are at least 12 px. |

Each `steps.json` entry includes actual visible heading/status/alert text and a separate Infra snapshot's current custody and queue counts; the test assertions verify the per-step behavior above.
