## Mail dependency

Every integration claimed as delivered: Switchback publishes notices to Mail through Messaging. Calendar is used only through its own Agent tools and is not a delivered connection.

| Field | Value |
| :--- | :--- |
| Source and destination | Switchback 0.1.0 (`switchback`, account `sb-dana`, person `person-dana`) to Mail 1.3.0 (`mail`, account `mail-dana`, same person), grant in [`../examples/messaging/config.json`](../examples/messaging/config.json) |
| Contract | `channel.email`, wire schema `urn:pale:email-message:2`, payload `urn:pale:email-payload:1`, type `org.pale.mail.notification.v1`, receiver operation `mail.receive_notification`; a pinned copy of Mail's wire schema validates every notice at commit |
| Caller and direction | Host-side publisher ([`../examples/publish-to-mail.cjs`](../examples/publish-to-mail.cjs)) calls `router.publish` on the reference Messaging router with publisher identity `switchback`; one direction, Switchback to Mail |
| Initial states | Switchback: `fixtures/minimal.json` plus the closure event `ev-0017` ([`../examples/scenario.json`](../examples/scenario.json)); Mail: [`../examples/messaging/mail-seed.json`](../examples/messaging/mail-seed.json) (empty inbox) |
| Command | `node apps/switchback/examples/publish-to-mail.cjs --evidence apps/switchback/evidence/mail-delivery.json` |
| Local commit | The closure commits `res-0001` as `closure_cancelled`, the refund payment and notice `sb-notice-0001` in one Switchback commit |
| Request | `request_id` `sb-notice-0001`, CloudEvents `id` `sb-notice-0001`, source `urn:pale:app:switchback:account:sb-dana`, recipient `person_ref` `person-dana` |
| Receiver commit | `status: committed`, `event_id` `router-9303ce1ab58bf0e462fdb5c4f46442d5`, target `mail`/`mail-dana`, applied at Mail's own clock |
| Read back | `mail.get` with that ID returns message `router-9303ce1ab58bf0e462fdb5c4f46442d5` in `mail-dana`'s inbox, subject "Closure: Cedar Flat stay res-0001 is cancelled with a full refund", body with the reservation, nights, reason, refund and posting date on labelled lines. [S9 step 5](screens/s9-05-result.png) shows it in Mail's own pages (run `evidence-mail`) |
| Retry | Same `request_id` again: `duplicate: true`, same `event_id`, Mail message count unchanged |
| Missing grant | [`config-no-grant.json`](../examples/messaging/config-no-grant.json): `rejected`, `recipient_not_authorized`; Mail and Switchback state unchanged |
| Unknown acknowledgement | Mail commits but the router's receiver call loses the reply (staged in-process, as in `runtime/messaging/tests/test_time_trace.cjs`; `runtime/` unchanged): `unknown`, `receiver_unconfirmed`, `stop_run: true`, attempted `event_id`, no commit time; the next publish is `halted`/`run_halted`; reconciliation reads Mail's `env.event_status` (committed once) and `mail.get` (message present); Switchback unchanged; the run is not scored |
| Incompatible contract | Not staged: the router refuses a message whose channel, schema or payload does not match the receiver before delivery (`incompatible_contract`); Switchback's business test fails any stored notice that does not validate against the pinned wire schema |
| Business confirmation | Not applicable: the notices go to the account holder's own mailbox; no recipient or business party confirms them |
| Required public dependencies | The pinned runtime, Mail 1.3.0 and the repository-level [`examples/registry.mail.json`](../../../examples/registry.mail.json) (named by the script and by the Messaging config) |

Messaging delivers at the receiver's current virtual time, so the Mail message's `received_at` is Mail's clock (2026-11-15 09:00 -08:00 from `examples/registry.mail.json`), not Switchback's. A run assembly that keeps both clocks together advances them with `env.advance_time` before publishing.
