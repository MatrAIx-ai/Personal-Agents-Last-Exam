# QuestShelf (PALE Environment Track App)

Multimodal cross-platform game library, negative-feedback recommender, and friend co-op poll hub built for PALE Core `1.2.0` (`runtime 1.6.0`, approved **MCP-only** scope with `ui: "none"`, zero App dependencies, zero external npm dependencies, MIT License).

- **Delivery evidence index:** [evidence/README.md](evidence/README.md)
- **2025–2026 evaluation dataset coverage report:** [evidence/coverage.md](evidence/coverage.md) (generated by `node scripts/coverage.cjs`)
- **Full 2025–2026 evaluation seed:** `datasets/eval-2025-2026/seed.json` (load via Infra `env.load_seed` at `virtual_now: "2026-12-31T12:00:00-08:00"`, or generate a pre-cutoff slice for any earlier clock via `node scripts/slice-dataset.cjs --cutoff <ISO>`)

## Package Highlights

- **Smoke fixtures & full 24-month evaluation dataset:**
  - `fixtures/minimal.json` (20-game default smoke fixture, `fixtures/clock.json` `2026-11-20T16:30:00-08:00`) and `fixtures/seed-casual.json` (alternate user profile).
  - `datasets/eval-2025-2026/seed.json` (100% synthetic evaluation dataset covering **2025-01-03 through 2026-12-30**, **24/24 months**, **175** unique user-activity events across **126** deduplicated dates — 71 `play_history` shelf events aligned with co-op sessions, 15 friend library acquisitions, 19 varied organic co-op polls including ties, split votes, weekend votes, missed votes, and a 0-vote cancellation, and 1 preference update; **195** unique events / **144** distinct dates including catalog metadata; regenerated deterministically by `node scripts/build-eval-dataset.cjs`).
  - `scripts/slice-dataset.cjs` rewinds shelves, preferences, friend libraries, polls, and catalog timestamps to any earlier ISO-8601 cutoff so Tasks can load a clock-consistent slice (e.g., `2025-06-15` or `2026-11-20`) with zero future leakage.
- **20 illustrated 640×360 synthetic PNG gameplay & HUD preview screenshots** (`assets/`, `117.5 KiB` total decoded bytes, strictly within the `64-asset / 1 MiB` budget, regenerated deterministically by `python3 scripts/render-previews.py`):
  - Visual cues (first-person corridor/lantern/vignette/EKG horror vs. isometric tile grids, top-down stations/kitchens/greenhouses, 2D side-scroll, 3rd-person, chase-cam racing, tactical grid, deckbuilder cards, arena sports, point-and-click) are depicted purely visually with **no printed camera/genre/pt-size captions** and neutral game summaries & `alt_text`.
  - In-game HUD typography is rendered proportionally to each game's `hud_font_pt` (`round(hud_font_pt * 1.45)` px), matching `fixtures/visual-cues.eval.json` (`handheld_hud_readable === (hud_font_pt >= 14)`).
- **14 MCP tools** (8 read-only, 6 versioned writes) + **3 Infra events** (`questshelf.game.update_patch`, `questshelf.friend.library_update`, `questshelf.poll.friend_vote`) with strict per-operation payload schemas (`schemas/events.schema.json` + `src/events.cjs`).

## Host Resource Registration Dependency (Maintainer / Infra Review)

Agent access to the 20 preview PNGs via MCP `resources/list`, `resources/read` (`pale://<run>/questshelf/assets/<asset_id>`), and `questshelf.asset.read` depends on **`runtime/registrations/questshelf.json`** (`game` → `questshelf.game.get`), which lives outside `apps/questshelf/` and requires maintainer/Infra review:

- Without `runtime/registrations/questshelf.json`, `npm run app:verify -- --app apps/questshelf` still passes its 42 common checks, while `resources/list` returns `0` resources and `questshelf.asset.read` returns `not_available` (Example 1's visual workflow cannot run).
- `node --test tests/mcp.test.cjs` explicitly exercises a real stdio Agent connection, asserts `resources/list` returns all 20 PNGs, verifies `resources/read` byte-for-byte SHA-256 parity against `contribution/assets.catalog.json`, and fails with a clear diagnostic if the registration is missing.

## Key Behavioral Guarantees

1. **Poll expiration visibility & side effects (`questshelf.poll.list`, `poll.create`, `poll.update`):**
   - Once `ctx.virtual_now > poll.closes_at` without an explicit `questshelf.poll.close`, the poll remains `status: "open"` while `questshelf.poll.list` sets derived `voting_expired: true`.
   - Both `questshelf.poll.vote` (`invalid_state`) and `questshelf.poll.friend_vote` (`invalid_event`) reject late votes atomically, while `questshelf.poll.close` remains callable to tally existing votes and seal `winner_game_ids`.
   - Because an expired poll remains `status: "open"`, `questshelf.poll.create` continues to return `conflict` until the Agent calls `questshelf.poll.close`; alternatively, `questshelf.poll.update` can extend `closes_at` later than `ctx.virtual_now` to re-open voting on the open poll.
2. **Prewritten events targeting Agent-created polls:** At most one `open` poll per account is allowed at a time. When `questshelf.poll.friend_vote` omits `poll_id`, QuestShelf deterministically matches the account's single `open` poll inviting `friend_id`, rejecting no-open-poll, closed/expired-poll, uninvited-friend, or non-candidate-game cases atomically as `invalid_event`.
3. **Structured-fields-only ranking & reversible drop feedback (`questshelf.recommend.rank`, `shelf.upsert`):**
   - Ranking uses only structured JSON fields (never image pixels or `visual-cues.eval.json`), preserving Example 1's multimodal trap on `game-lantern-hollow`.
   - Active avoid reasons are computed dynamically as the union of `preferences.avoid_reasons` and `drop_reasons` on currently `dropped` shelves (`src/model.cjs`). Dropping a game does **not** permanently mutate `preferences.avoid_reasons`; moving the shelf back from `dropped` to `playing` or `backlog` clears its `drop_reasons` and restores the original ranking.
   - Completed games contribute positive `likedTags` **only** when `rating >= 8.0` (unrated `rating: null` completions are excluded).
   - `drop_reasons` ranking behavior: `first_person_motion_sickness` excludes `first_person`; `horror` excludes `horror`; `excessive_grind` excludes `excessive_grind`; `tiny_ui_text` excludes `tiny_ui_text` or `hud_font_pt < 12`; `too_long` excludes `playtime_hours.main > 20`; `no_offline_mode` excludes `offline_ok: false`; `other` is stored as structured user metadata without an automatic filter.
   - Shelf transition & `play_history` rules:
     - `completed` → `backlog` rejects atomically (`invalid_state`). Replaying a completed game (`completed` → `playing`) is permitted, and any shelf whose `play_history` records a prior `completed` status continues to reject transitions back to `backlog` (`invalid_state`). Shelving an unfinished game (`playing` / `dropped` → `backlog`) clears `rating` and `drop_reasons`.
     - `hours_logged` is monotonically non-decreasing across updates (`questshelf.shelf.upsert` rejects a lower `hours_logged` with `invalid_arguments` consistently on all shelves).
     - `backlog` rejects non-null `rating` (`invalid_arguments`), and `drop_reasons` are only permitted when `status === "dropped"`.
     - `play_history` is an append-only rolling log capped at the 100 most recent entries per shelf (older entries are trimmed automatically so repeated `shelf.upsert` calls never fail schema validation). Every `questshelf.shelf.upsert` records a snapshot in `play_history` (initializing it on newly added shelves and on legacy fixtures without prior history).
4. **Strict per-operation event payload validation:** `schemas/events.schema.json` (using `oneOf` per operation with `additionalProperties: false`) and `src/events.cjs` reject unknown/misspelled fields, out-of-range `hud_font_pt` (outside `6..36`), and invalid types atomically without mutating state or revision.

## Local Setup & Verification

Requires Node.js 18+ (no `npm install` needed).

```bash
# 1. Standalone App-only unit tests & event example (works outside the repo)
cd apps/questshelf
npm test
npm run example

# 2. Reproducible 2025-2026 dataset coverage report
npm run coverage

# 3. Real stdio MCP tests (20 PNG resources/list + resources/read SHA-256,
#    eval-2025-2026 env.load_seed, drop/undo ranking, event schema controls)
#    Set PALE_RUNTIME_ROOT=/path/to/runtime when running from a standalone copy
npm run test:mcp

# 4. Full PALE public runtime verification (from repo root)
npm run app:verify -- --app apps/questshelf --output .artifacts/questshelf.json
```

## Loading the 2025–2026 Evaluation Dataset via Infra MCP

To load the full 24-month evaluation dataset (12-hour open window before the active NYE poll closes at `23:59`), pass `virtual_now: "2026-12-31T12:00:00-08:00"` (from `datasets/eval-2025-2026/clock.json`):

```json
{
  "expected_version": { "epoch": 1, "revision": 0 },
  "request_id": "load-eval-2025-2026",
  "data": "<contents of datasets/eval-2025-2026/seed.json>",
  "virtual_now": "2026-12-31T12:00:00-08:00"
}
```

> **Clock enforcement & slicing for earlier Task cutoffs:** `validateSeed` rejects any seed containing historical records dated after `ctx.virtual_now` (`invalid_seed`), preventing future-history leakage. To load QuestShelf at any earlier clock in 2025–2026 (such as `2025-06-15` or `2026-11-20`), generate a validated pre-cutoff slice first:
>
> ```bash
> cd apps/questshelf
> node scripts/slice-dataset.cjs --cutoff 2026-11-20T09:00:00-08:00 --output /tmp/questshelf-2026-11-20.json
> ```

## Scope & Limitations

- 100% synthetic fixtures and generated PNG previews (MIT License); no live store APIs, DRM downloads, payments, or external network access.
- Approved scope is **MCP-only** (`ui: "none"` in v1); GUI acceptance items are N/A.
- No declared App dependencies (`dependencies: []`); optional Mail 1.3.0 invitations are deferred post-v1.
- Local asset bundle budget: at most 64 assets / 1 MiB decoded bytes (currently 20 assets / 117.5 KiB).
