# SignalDesk

SignalDesk runs a fictional three-line mobile account in the PALE local reference runtime. From the repository root, use Node 18+:

```sh
node runtime/web/server.cjs --app signaldesk --registry apps/signaldesk/registry.json
npm run app:verify -- --app apps/signaldesk --output .artifacts/signaldesk.json
node --test apps/signaldesk/tests/business.test.cjs
```

Open the local access link printed by the server. The Account page shows line usage. Compare plans lists monthly prices and allowances. Manage plan and Roaming passes let the owner preview terms, confirm or discard the change, then inspect the receipt under Statements & notices. Rates are synthetic USD cents. All dates and monthly boundaries use UTC. Mobile data amounts use decimal MB.

## Time and accounting

Infra sets Core time and injects the two declared events. The seed starts the task at 2026-01-01 with synthetic activity dating back to 2025-01-01. A read projects all due effects on a copy. A successful write or event settles them once. At equal times the monthly plan change precedes pass expiry and activation. Charge IDs identify their cycle or pass. The task chooses the order of external events with the same instant. Usage events represent usage at event time. Domestic and hotspot usage draw on the shared pool. Hotspot also has a per-line ceiling. Covered roaming consumes the line's monthly inclusion followed by its covered active pass. Usage outside an allowance is recorded without an extra purchase.

## Fixtures and access

Run `node apps/signaldesk/fixtures/build.cjs VARIANT` to print one full seed. Variants are `ordinary`, `pending`, `near-limit`, `scheduled`, `active-expired` and `member`. Load the member seed with `fixtures/member-policies.json` through Infra. Seed replacement and reset follow Core semantics. The member can inspect their line and applicable plan terms. Only an owner can change household service. Infra validates external account updates against the bound owner.

Use `examples/scenario.json` for usage posting. A second example under `examples/account-update.json` cancels the pending change in the pending fixture. A preview records the target, price, dates and current terms. Confirm with the version returned by the preview. Abandon or recreate a preview if intervening activity has changed the version.

The installed package needs only Node built-ins for business tests. Integration and GUI require the public Core and shared Web Host. The local registry pins the package and initial time. Third-party services, live carrier data and real payments are outside the simulation. Code and generated fixtures use the included MIT license. Workflow design references are the public Google Fi and T-Mobile guides linked in the approved proposal.

## Reproduce the browser checks

The v1 baseline uses PALE runtime 1.6.0 and Core API 1.2.0 from upstream commit `a4bce023953061483c41de5a287ba5e43f4a5648`. Run these commands from the repository root:

```sh
npm ci
npx playwright install chromium
node apps/signaldesk/tests/browser.cjs
```

Alternatively set `SIGNALDESK_BROWSER` to an installed Chromium or Chrome executable. The test starts a loopback Web Host with temporary state, clicks through all five workflows, inspects the same run through MCP, then closes the browser and removes the temporary state. It also exercises a clock-only advance, two reset/replays, competing writes and a restricted member session.

## Data and reuse

The catalog in `src/catalog.cjs` defines the three plans, two pass products, prices, units and six coverage destinations. These are invented terms. Synthetic traffic is generated by `fixtures/usage-history.cjs`; `fixtures/build.cjs` adds household lines, monthly charges and scenario-specific records. The default seed can be reproduced with `node apps/signaldesk/fixtures/build.cjs ordinary`. Counts in the dataset manifest describe the three primary line records. Prices, household names and usage records are fixture data.

Public workflow references reviewed for the proposal on 2026-11-21: [Google Fi plan changes](https://support.google.com/fi/answer/9462005?hl=en), [Google Fi group roles](https://support.google.com/fi/answer/7131470?hl=en), and [T-Mobile data passes](https://www.t-mobile.com/support/plans-features/data-passes).
