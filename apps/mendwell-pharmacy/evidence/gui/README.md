# Mendwell GUI workflow sequences

Generated by `node apps/mendwell-pharmacy/evidence/tools/gui.cjs` (do not edit by hand). The steps are those of the browser acceptance `tests/web.browser.cjs`, run unchanged inside a recorder: each was performed with real controls in Chromium on the shared Web Host, and each step's action, expected result and checks come from that file. After each step the script read the App's persisted state through a separate Infra MCP client on the same run, then froze the step: it waited until no call the step made was outstanding, read the App's state and version, and stopped if the version had changed since before the check. The observations (the test's own reading of the state, and every record that changed since the previous step), version and virtual time below come from that frozen state; the script then scrolled the checked element into view (outlined in orange), checked that it is on screen, and only then took the screenshot; it then decoded the PNG and checked that the outline is in it (`outline_check` in `run.json`). Each step ends at its last check, so the screenshot shows the state the step asserts; restoring state for later steps is a step of its own. A failed check stops the script, so every step below is observed as expected. Every call is owned when it is sent, by the step open at that moment: page reads and tool discovery in every tab, the page's own writes and previews (`POST /api/call`), forced calls from the page's business session, Agent reads and writes through the Web Host's business client, Infra events, clock moves, seed loads, confirmations applied by `dev/confirm.cjs` and the inspector's own snapshot reads. A call sent with no owner, or after a step is frozen, stops the script; a submitting step lists a write or forced call that reached the Web Host. Each call has exactly one terminal outcome; a failure stops the script unless the step declared it beforehand as induced by the test (a connection dropped on purpose), in which case it is listed with its cause and `reached_host`: `false` when the call was dropped before it reached the Web Host (it does not count as submitting), `true` when the reply was dropped after Mendwell committed it. Page writes and previews are listed with the raw arguments (tokens and versions included, unshortened) and the raw reply. Agent writes and previews, Infra events, clock moves and forced calls are listed raw, except that the host wall-clock fields `received_at` and `processed_at` in Infra event receipts and the random event ID that `dev/confirm.cjs` draws are replaced by notes so that repeated captures are identical; Agent reads are summarized; seed loads are named by file and by the tools a policy omits; page reads that Mendwell refuses or answers with an HTTP error, and tool discoveries that fail, are listed with their raw reply (Mendwell's status and version included). Not listed, but owned and waited for: page reads answered with HTTP 200 and status `ok` and tool discoveries answered with HTTP 200 (what the page loads at start, after each action and on Refresh), and the inspector's own `env.snapshot` reads, whose content is the step's observed state. A reply the test supplies or changes with Playwright's `route.fulfill` is listed whatever its status and labelled: **injected** when the test built it and the call never reached the Web Host, so nothing in it was committed and the step does not count as submitting; relayed when it is the Web Host's own reply passed on unchanged; **altered** when the test changed it. Before capturing, the script runs the 27 recorder probes in `evidence/tools/probes.cjs`; each must make the recorder stop with its exact expected message or show the declared outcome, and the results are in `run.json` (`recorder_probes`). The capture runs Chromium with software rasterization on one thread and replaces the page's random request IDs with a counter, so two runs on the same machine give the same screenshots and step data; on another machine or Chromium build, anti-aliased edges can differ by a few pixels.
