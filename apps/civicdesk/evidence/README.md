## 2. Declared App dependency: Mail 1.3.0 (send-only notices)

`mail-notice-trace.json` is written by `node apps/civicdesk/examples/mail-notice.cjs apps/civicdesk/evidence/mail-notice-trace.json` and records 17 checks over real MCP processes (CivicDesk and Mail instances in one run; the Messaging service as a separate publishing process):

- CivicDesk and Mail clocks advanced to the session time with `env.advance_time`; the agent reads the target docket with its Eastern deadline, drafts an anonymous comment, is refused without the acknowledgment, and submits with it: tracking number `CDK-2026-0031-10166`.
- The host-run publisher reads the committed comment over the Agent connection and publishes the receipt notice through Messaging; the receipt event is `router-6cbffd7d7ab87e730186d11ec2e44b93`, and Mail's record `router-6cbffd7d7ab87e730186d11ec2e44b93` holds the notice unread with the same tracking number. Publishing itself changes nothing in CivicDesk.
- Infra records the delivered outcome on the comment with `comment.notice_recorded`; `comments.status` then shows it in the comment's notice history.
- A publisher configured without a recipient grant is rejected with `recipient_not_authorized`; Mail is byte-identical before and after, and the rejection is recorded on the comment, which stays submitted.
- A replay of the same `request_id` returns the first receipt with `duplicate: true`; a new request ID for the same notice deduplicates on the CloudEvents `(source, id)`; Mail's message count does not change.

The Messaging configuration is `examples/router.json` (publisher `civicdesk`, account `acct-dana`, one grant to Mail account `mail-dana` on `channel.email`). The wire schema copy `schemas/router-message.schema.json` is byte-identical to Mail's; `tests/business.test.cjs` validates both notice kinds against it and against `email-payload.schema.json`. Calendar and Files are reached only by the agent's own tools; CivicDesk sends nothing to them.

## 4. GUI: implemented screenshots and ordered workflow sequences

`capture.cjs` starts the public Web Host for this App, drives a real headless Chrome over the DevTools protocol (no npm packages), performs each workflow through the actual controls, checks the persisted state over the Infra MCP connection after every write, and writes `screenshots/*.png` (1280×900) plus `gui-sequences.json`. Captured with Chrome/158.0.8127.37 on Node v24.16.0; 12 screenshots, 17 checks, all passing. Reproduce with `node apps/civicdesk/evidence/capture.cjs` (set `CHROME_PATH` if Chrome is not found).

| Step | Workflow | State | What it shows | Checks |
| --- | --- | --- | --- | --- |
| 01-dockets | dockets | start | Dockets open for comment, soonest deadline first, with days left, extensions, corrections and the member's own comments flagged | 1/1 |
| 02-docket | dockets | intermediate | Docket page: summary, supplementary information, the deadline in the agency's time zone (Eastern), documents and the comment control | 1/1 |
| 03-document-downloaded | dockets | result | Downloading the notice saves the document; its bytes match dockets.documents byte for byte | 1/1 |
| 04-draft-problems | comments | error | A short, named draft without a name is saved but reported: too short and name required; nothing can be submitted yet | 2/2 |
| 05-review | comments | intermediate | Review step: the final text, how the member appears (anonymous), the deadline, and the acknowledgment that the comment is public and permanent | 1/1 |
| 06-submit-unacknowledged | comments | error | Submitting without the acknowledgment is refused; nothing is submitted | 2/2 |
| 07-receipt | comments | result | Receipt: tracking number, anonymous submission, submission time in the agency's time zone, the text as submitted, history | 2/2 |
| 08-my-comments | comments | intermediate | My comments: the new submission as received, earlier comments posted | 0/0 |
| 09-duplicate-refused | comments | error | A second non-supplemental comment on the same docket is a possible duplicate; the page offers the supplemental option instead | 1/1 |
| 10-closed-docket | dockets | error | A closed docket offers no comment control; its closing date and the member's posted comment are shown | 2/2 |
| 11-extended | dockets | result | After Infra applied the extension event, the docket shows the new Eastern deadline and the date it was extended from; the member's comment stands | 2/2 |
| 12-posted | comments | result | After Infra applied the status event, the comment reads posted on its receipt page | 2/2 |

Error paths covered: a short, named draft without a name is reported before it can be submitted; a submit without the acknowledgment is refused and stores nothing; a second non-supplemental comment on the same docket is a possible duplicate; a closed docket offers no comment control. The extension and status events are applied through Infra (`env.apply_event`), never by the page. Not yet captured: a supplemental submission and a returned comment, which the business tests cover.
