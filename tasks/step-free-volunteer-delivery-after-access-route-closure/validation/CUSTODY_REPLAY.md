# Consent and receipt replay preflight (partial author-side validation)

Implements a conservative chronology check for F2, F3 and a candidate E2 receipt path, not the full LifePack rubric. Inputs must be normalized by a trusted Infra/verification adapter from actual committed Mail/Calendar traces and scripted event receipts. The adapter must establish the origin, sender identity, message meaning, item mapping and commit-time ordering; this module does not infer these from free-form text or from an agent-written report. Equal timestamps are treated conservatively for consent (no transfer without strictly earlier acceptance); the final adapter must preserve authoritative event order and handle any legitimate same-timestamp ordering. The code does not award E2 points on its own. It does not assess F1/E1, route truth, notifications, duplicate revisions, cancellation history, or actual delivery, and errors require adapter review, not automatic task failure. The approved proposal was not changed.

18 deterministic synthetic regression checks passed in a JavaScript execution environment using the exact function bodies written here. Run `node test_custody_replay.cjs` to reproduce. No real Mail/Calendar/App or full LifePack evaluation was run. Actual adapter integration and official model trials remain pending. See the approved proposal and the existing route replay module for separate contracts. The actual shared Mail and Calendar tool schemas on main were inspected; this normalized event interface deliberately does not claim to be a native App state schema.
