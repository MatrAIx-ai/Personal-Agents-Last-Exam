## 2. What you plan to build

**✍️ Your answer (required):** Lintel is a resettable rental app covering both ends of renting: finding a place (search, saved searches, tours with exclusive slots, applications with a fee charged once) and keeping one (lease terms, renewal offers with several term options, landlord offers, notice to vacate). The writes that matter are final or cost money, and the right one depends on dates and plans that are not in the request.

Eight workflows, each end to end including change and cancellation:

1. **Search.** Filter listings by rent, bedrooms, pets, move-in date, lease length and neighborhood. Listing detail shows fees, deposit and the lease terms on offer.
2. **Saved searches.** Save a search and get a dated digest of new and changed matches.
3. **Tours.** See open slots, hold one with a preview, confirm, reschedule or cancel. Slots are exclusive, and one can be taken by another renter between preview and confirm.
4. **Applications.** Start an application, attach the required documents, preview the fee, submit once. The fee, once paid, covers further applications for 30 days, so what a submit costs depends on what the user already paid. Status moves by event (received, more information needed, approved, rejected). A listing can be withdrawn while an application is open.
5. **Lease.** Read the current lease: term, rent, deposit, break clause, notice period, early-termination charge and renewal window.
6. **Renewal.** Read the landlord's offer and its deadline, ask for terms that are not offered by default (a shorter term, a break clause), preview what an option costs and what leaving would cost, then accept or decline. If the deadline passes unanswered, the default stated in the lease applies.
7. **Landlord offers.** Accept or decline a mid-term offer before its deadline, for example a cash incentive to convert to a longer term.
8. **Notice to vacate.** Preview the earliest penalty-free end date and any charge, confirm, or withdraw while the lease allows it.

Housing requests are underdetermined on their own. "Renew like always" or "book the Saturday tour" is right or wrong depending on a possible job change, a lease that ends six weeks before the new one starts, or a neighborhood the user ruled out after an earlier visit, and those facts sit in history and in other apps. The costs are concrete: a slot someone else took, a fee that is charged once, a 24-month term with a penalty for leaving. Every outcome a task is likely to grade is a stored field with a receipt (which slot, which term, what it cost, when it was confirmed), so a grader can read state instead of judging a transcript.

### Integration details

- **Operations and access (required):** Agent-facing MCP tools (32): `lintel.listings.search|get`, `lintel.saved_searches.create|list|delete`, `lintel.alerts.list`, `lintel.tours.slots|list|reschedule|cancel`, `lintel.tours.book.preview|confirm`, `lintel.applications.start|update|get|list|withdraw`, `lintel.applications.submit.preview|confirm`, `lintel.lease.get`, `lintel.renewal.get|request_terms|decline`, `lintel.renewal.accept.preview|confirm`, `lintel.offers.list|respond`, `lintel.notice.preview|confirm|withdraw`, `lintel.payments.schedule`, `lintel.policies.get`. Reads commit nothing. Every write takes `request_id` and `expected_version`. Approval-gateable: `tours.book.confirm`, `applications.submit.confirm` (charges the fee), `renewal.accept.confirm`, `offers.respond` and `notice.confirm`. A GUI renderer serves the same records as seven pages (search, listing, tour booking, application, lease, renewal, notice) for computer-use agents. Platform operations for reset, seed load, snapshot and event injection will take the names and signatures of the first infrastructure release; the business model sits behind a thin interface layer so that change is cheap.
- **State and lifecycle (required):** Catalog state (listings, landlords, slot calendars, lease templates, policies), account state (saved searches, tours, applications, lease, renewal and offer responses, notice, payment ledger) and run state (last clock time seen, open previews, applied event IDs and request IDs, ID counter) are separate. A seed validator checks references and dates, and that every renewal option's total cost can be recomputed from stored terms. Reset reloads the seed and clears run state. A snapshot captures account and run state, including every write receipt, and restores to an identical state hash. Previews expire after 15 simulated minutes. A confirm must name a live preview; if the slot, listing or offer changed since the preview it returns a conflict and applies nothing. A repeated `request_id` returns the original receipt, or an error if the payload differs; a stale `expected_version` applies nothing. IDs come from the counter and times from the platform clock, never the wall clock.
- **Events and notifications (required):** Events use `{event_id, at, type, payload}`. Scripted by the task: `listing.posted`, `listing.price_changed`, `listing.withdrawn`, `tour.slot_taken` (another renter), `tour.cancelled_by_landlord`, `application.status_changed`, `renewal.offer_issued`, `offer.issued`, `clock.advance`. Example: `{"event_id": "e7", "at": "2027-06-10T09:00", "type": "offer.issued", "payload": {"lease_id": "L1", "kind": "convert_term", "term_months": 24, "incentive": 500, "respond_by": "2027-06-24"}}`. Clock-driven: saved-search digests, preview expiry, renewal and offer deadlines (the lease's stated default applies if unanswered) and the earliest penalty-free end date. Notifications: Mail for tour confirmation and cancellation, application receipt and decision, renewal offer, landlord offer and digest; a Calendar invite on tour confirm, withdrawn on cancel. Each notification carries the IDs of the records it refers to.
- **Shared data and dependencies (required):** Stable IDs for person, account, listing, landlord, agent, tour slot, tour, application, document, lease, renewal offer, term option, landlord offer, notice, payment and receipt; seeded records keep their IDs so task events can address them. People are referenced by contact ID where Contacts exists. Lease and renewal documents are text or PDF assets by asset ID. Listings use locally generated floor-plan SVGs, no photographs. Needs shared Mail, Calendar and the platform clock; nothing external at run time.
