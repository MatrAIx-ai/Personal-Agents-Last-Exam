# Environment Track proposal

Proposed PR title: `[Environment Proposal] [Work & business] Beacon job board and professional network (LinkedIn-inspired)`

## 1. App and domains

- **Authors / GitHub handles (required):** Sunny Yuan ([@ZichenYuan](https://github.com/ZichenYuan)).
- **Reference app or website / URL (required):** Beacon, an independently branded synthetic job board and professional network; interaction patterns reference LinkedIn Jobs (https://www.linkedin.com/jobs/) and public help pages only. No LinkedIn code, assets or data are used.
- **Primary domain (required):** Work & business
- **Secondary domains (optional):** None

## 2. What you plan to build

**✍️ Your answer (required):** A resettable job board and professional network where a user searches postings that carry level, workplace type, salary, sponsorship language, source and status; saves searches that send thin daily alert digests to Mail; applies with a chosen resume and tracks application status; maintains a profile, resumes and open-to-work settings including who may see them; messages recruiters with attachments; and follows companies whose pages show parent and subsidiary relationships. Postings open, repost and close, recruiters write and nudge, and application statuses change on the simulated clock, so career tasks can run for weeks.

Initial workflows, each complete end to end including modification, cancellation, confirmation and realistic errors:

1. **Job search and postings.** Search by keywords, location, workplace type (on-site, hybrid, remote), experience level, date posted, company and salary range. A posting page shows title, company, location, workplace type, stated level, salary range (sometimes absent), description, requirements, posted and reposted dates, applicant count, status (open, paused, closed), source (company career site or aggregated repost), and whether it accepts an in-app application or hands off to an external site. The catalog contains realistic noise: the same role reposted with a new date, the same role on an aggregated copy with a stale status, titles whose stated level disagrees with the requirements, and sponsorship or clearance conditions buried in the description.
2. **Saved searches and alert digests.** Create a saved search from any filter set with a cadence (instant, daily, weekly); the app sends thin digest emails to Mail listing only title, company, location and a link, as real alert emails do; pause, edit, resume and delete; a digest never repeats a posting already sent for that search.
3. **Applications.** In-app application with resume selection, screening questions and a confirmation step; external applications hand off and are recorded as "applied externally" with a user-entered date; status timeline (submitted, viewed, in review, interview, rejected, offer); withdraw; errors for a closed posting, a duplicate application, a missing required answer or an oversized resume.
4. **Profile, resumes and open-to-work.** Profile with headline, experience, skills, location and languages; several uploaded resumes with a default; open-to-work preferences (titles, locations, workplace types, start date) with a visibility setting that can hide the signal from the current employer's recruiters; profile-view records.
5. **Messaging and recruiters.** Inbox of recruiter messages and InMail with attachments; reply, decline with a reason, archive; recruiter nudges and interview proposals arrive as events; new-message notifications are published to Mail and interviews to Calendar.
6. **Companies and connections.** Company pages with industry, size, ratings and review count, parent and subsidiary relationships, open roles and the user's connections there; follow and unfollow; connection list and requests for referrals.

Value for personal-agent tasks: a career move is one of the most personal decisions an agent can help with. The right posting depends on goals, true level versus title, location and sponsorship constraints, a salary floor, a current employer that must never see the search, companies the user has already applied to or sworn off, and recruiters already in conversation. The author's reviewed PersonalAgentEval cases supply downstream tasks on this environment: a daily job scan tuned to the user's goals and level (submitted alongside this proposal as a linked Task PR), replying to recruiters with the right resume through the user's own tools, timing a follow-up after interviews, and a job-alert digest whose facts must match their source.

## 3. Potential app connections

- **Internal personal apps (required):** Mail: alert digests, application status notices, new-message notifications and interview invitations arrive here. Calendar: interviews and application deadlines. Files: resumes, cover letters and the user's career notes. Contacts: recruiters and referrers, read only, TBD pending a Contacts app.
- **Other apps and websites (required):** Company career sites are represented inside the environment as external-application handoffs; a standalone career-site environment is deferred. A compensation-data site is a potential future link; the initial scope keeps salary ranges on postings.

### Integration details

- **Operations and access (required):** Agent-facing MCP operations: `jobs.search|get|similar`, `saved_searches.create|list|update|pause|resume|delete`, `applications.start|answer|submit|list|get|withdraw|record_external`, `resumes.list|upload|set_default|delete`, `profile.get|update`, `open_to_work.get|set`, `messages.list|get|reply|decline|archive`, `connections.list|request`, `companies.get|follow|unfollow|subsidiaries`, `people.search`. Approval-gated writes: `applications.submit`, `messages.reply`, `profile.update`, `open_to_work.set` and `connections.request`. A GUI renderer presents job search, posting, company, saved searches, applications, application form, profile, resumes, messages, thread, connections and people search pages for computer-use agents. Platform-facing operations: `env.reset`, `env.load_seed`, `env.snapshot`, `env.inject_event`.
- **State and lifecycle (required):** App state (companies with relationships, postings catalog with schedules, recruiters, people) is separated from account state (profile, resumes, saved searches and their sent history, applications, messages, connections, follows) and run state (clock, pending application drafts, event log). Seed validation checks posting dates, company references, duplicate groups and level and salary fields; reset restores the seed and clears drafts and digest history; an application draft expires after a configured simulated interval; submit is idempotent by draft ID; a posting that closes between draft and submit returns a conflict error.
- **Events and notifications (required):** Accepted events: `jobs.posted`, `jobs.reposted`, `jobs.closed`, `jobs.paused`, `jobs.salary_updated`, `alerts.digest_due` (clock-driven per saved search), `applications.status_changed`, `messages.received` (recruiter message, nudge or interview proposal), `profile.viewed`, `connections.requested`, `companies.updated` (for example a subsidiary added). Published notifications: text emails to Mail for digests, application status, new messages and profile views, and calendar updates for interviews, following the shared Mail and Calendar apps' formats. Task scenarios decide when events occur.
- **Shared data and dependencies (required):** Stable IDs for the person, account, company, posting, duplicate group, application, message thread, recruiter and connection; resumes and attachments as PDF or text assets addressed by asset ID. Depends on the shared Mail, Calendar and Files apps and the platform clock; no external service at run time.
