## 2. What you plan to build

**✍️ Your answer (required):** ShelfMark Public Library is a resettable, independently branded municipal library simulator where routine actions can succeed on the portal and still fail a patron's real constraints. Real library patrons juggle physical holds across multiple city branches, freeze/suspend holds before travel so they keep their queue position without forfeiting pickup windows, renew loans only when no other patron is waiting, manage linked household/child library cards that become blocked when overdue fines exceed a threshold, dispute fines for returned items, and book time-limited study rooms or museum passes with strict cancellation cutoffs. A personal agent must respect household card authority, travel dates, format preferences (`print`, `large_print`, `audiobook`, `museum_pass`), and virtual-time deadlines rather than blindly cancelling holds or paying unverified fines.

Core reusable workflows (entities, state transitions, reads/writes, and failure/control paths):

1. **Search multi-branch catalog and inspect real-time availability (`catalog_title` & `branch_copy`: `available | checked_out | on_hold_shelf | in_transit`):**
   - *Reads:* search/filter titles by keyword, author, ISBN, format (`print`, `large_print`, `audiobook`, `ebook`, `museum_pass`, `library_of_things`), subject, branch availability or hold-queue length; inspect copy status across branches.
   - *Failure/control:* unknown title ID returns `not_found`; filtering by an unknown branch ID returns `validation_error`.
2. **Place, suspend/resume, redirect and cancel holds (`hold`: `queued -> suspended -> queued -> ready_for_pickup -> checked_out | expired | cancelled`):**
   - *Reads/writes:* place a hold specifying pickup branch and managed `card_id`; suspend/freeze a `queued` hold until a virtual-time `resume_at` date while preserving queue position; change pickup branch while `queued` or `suspended`; cancel a hold cleanly.
   - *Virtual-time & offline transitions:* `env.advance_time` never mutates records or sends notices. Reads (`hold.list`/`hold.get`) derive `effective_status` (`expired` when `virtual_now > pickup_expires_at`, or `queued` when a `suspended` hold has `virtual_now >= resume_at`) without mutating state, and subsequent writes or Infra events commit those derived transitions. Advancing the queue to `ready_for_pickup` happens exclusively via Infra `hold.ready_for_pickup`, and physical checkout happens via Infra `hold.checked_out`.
   - *Failure/control:* placing a hold on a card with `card_status: blocked_fines` fails with `ACCOUNT_BLOCKED`; placing a duplicate active hold for the same title and card fails with `DUPLICATE_HOLD`; suspending a hold already `ready_for_pickup` fails with `invalid_state_transition`; stale `expected_version` returns Core `stale_version`.
3. **Manage loans, renewals and linked-card fines (`loan`: `active -> overdue -> returned`; `fine`: `open -> disputed -> paid | waived`):**
   - *Reads/writes:* list active loans across the parent account and its seed-declared `managed_cards[]`; renew an eligible loan; preview a fine payment amount (`fine.preview_payment`) and confirm payment (`fine.pay`, unblocking the card once total open balance drops below `block_threshold_cents`); or submit a fine dispute (`fine.dispute`) referencing a returned item or receipt.
   - *Virtual-time & offline transitions:* Reads derive `effective_status: "overdue"` when `virtual_now > due_at` without mutating state. Physical returns arrive via Infra `loan.returned`, new fines via `fine.assess`, and library dispute resolutions (`waived` or `open`/denied) via `fine.dispute_decided` (recomputing `card_status` automatically).
   - *Failure/control:* renewing a loan that has waiting holds (`queued_patrons > 0`) fails with `RENEWAL_BLOCKED_BY_HOLD`; renewing past `max_renewals` fails with `RENEWAL_LIMIT_REACHED`; paying an already-paid/waived fine with a new `request_id` fails with `invalid_state_transition`, while retrying with the same `request_id` returns Core `duplicate: true` without charging twice.
4. **Book and cancel study rooms and museum passes (`room_booking`: `confirmed -> cancelled | no_show`):**
   - *Reads/writes:* search available study rooms by branch, capacity, whiteboard/AV amenities and time slot, or museum passes by date; book or cancel a reservation. Offline missed bookings are recorded via Infra `room_booking.no_show`.
   - *Failure/control:* booking an overlapping slot fails with `SLOT_CONFLICT`; exceeding daily household room-hour quota fails with `QUOTA_EXCEEDED`; cancelling strictly past the free-cancellation cutoff (`virtual_now > free_cancel_cutoff_at`) records a late-cancellation flag unless waived by Infra `branch.closure`.

Reuse across distinct task situations: (a) a patron leaving for a 10-day trip must suspend two queued holds until their return date (preserving queue rank rather than cancelling), redirect a third hold to a branch near work, and renew an active loan before it becomes overdue; (b) a parent managing a linked child card blocked by overdue fines must inspect the fine ledger, dispute a fine for a book already returned via `loan.returned`, preview and pay only the remaining valid balance to unblock the card, and place a hold on a school-project title; (c) a student organizing a study group must rebook an affected study room at another branch without penalty after a `branch.closure` event. Every task seeds its own branches, catalog, managed household cards, queue positions, loans and room slots cleanly.

Overlap acknowledgement (checked against `proposals/proposal-list.md` on 2026-11-24): `#50` (Community Lending Library) also covers holds, queues, loans/returns and renewals blocked by other patrons' holds in a single-location tool/community library without fines. ShelfMark Public Library covers a distinct multi-branch municipal public-library scope: cross-branch pickup routing, linked parent/child household cards with fine-threshold blocking and dispute resolution, study-room/museum-pass bookings, and branch-closure deadline extensions. The other `Public service & law` proposals are `#16` (CivicDesk, municipal 311/permits) and `#125` (Ridgeway MVD, motor-vehicle licensing).

### Integration details

- **Operations and access (required):**
  - **Agent-facing business operations** (all prefixed with `shelfmark-library.` per runtime registration rules; exposed via `agent-mcp` stdio tools and the shared Web Host GUI reading/writing the same authoritative state; every write requires `expected_version` and `request_id`):
    - `shelfmark-library.catalog.search` / `shelfmark-library.catalog.get` (`MCP` + `GUI`, `read`): search/filter catalog titles and inspect multi-branch copy availability and queue depth.
    - `shelfmark-library.card.list` (`MCP` + `GUI`, `read`): inspect the parent library card and seed-declared `managed_cards[]`, open fine totals, and `card_status` (`active | blocked_fines`).
    - `shelfmark-library.hold.list` / `shelfmark-library.hold.get` (`MCP` + `GUI`, `read`): list or inspect holds with virtual-time-derived `effective_status`.
    - `shelfmark-library.hold.place` / `shelfmark-library.hold.suspend` / `shelfmark-library.hold.resume` / `shelfmark-library.hold.change_branch` / `shelfmark-library.hold.cancel` (`MCP` + `GUI`, `write`): full hold lifecycle.
    - `shelfmark-library.loan.list` / `shelfmark-library.loan.renew` (`MCP` + `GUI`, `read`/`write`): inspect loans (with derived `overdue` status) and renew eligible loans.
    - `shelfmark-library.fine.list` / `shelfmark-library.fine.preview_payment` / `shelfmark-library.fine.pay` / `shelfmark-library.fine.dispute` (`MCP` + `GUI`, `read`/`write`): inspect fines, preview exact payment total and unblock impact, confirm payment, or submit a dispute.
    - `shelfmark-library.room.search` / `shelfmark-library.room.list_bookings` / `shelfmark-library.room.book` / `shelfmark-library.room.cancel` (`MCP` + `GUI`, `read`/`write`): study-room and museum-pass reservation lifecycle.
  - **Infra-only privileged operations** (strictly on `infra-mcp`, unavailable to the Agent and absent from the Agent Web GUI): the six baseline operations (`env.load_seed`, `env.apply_event`, `env.reset`, `env.snapshot`, `env.event_status`, `env.validate_bundle`), plus Core's host clock `env.advance_time`.
  - **Reviewer console:** None inside the Agent GUI; inspection uses Core's administrative snapshot/audit interface and standalone reviewer renderer (`gui/src/view.js`).
- **State and lifecycle (required):**
  - **State separation & household card authority:** Catalog state (`branches[]`, `titles[]`, `rooms[]`, `queue_positions`), single bound parent account state (`account_id`, `owner_person_id`, seed-declared `managed_cards[]` listing parent and linked child cards with explicit authority, `holds[]`, `loans[]`, `fines[]`, `room_bookings[]`), and run-level Core isolation (`run_id`, `app_id`, virtual clock, receipts and audit log). Authority over linked child cards comes strictly from ShelfMark's seed data, never inferred from Contacts.
  - **Commit evidence, retries and concurrency:** All writes use Core's native `{status: "committed", app_id: "shelfmark-library", version: {epoch, revision}}` envelope and Core's `stale_version` optimistic concurrency check. Same-`request_id` retries return Core `duplicate: true` without mutating state or double-charging fines; changed arguments with a reused `request_id` return `idempotency_conflict`. App-owned receipt fields (`hold_id`, `payment_receipt_id`, `booking_confirmation_code`) are returned alongside the Core envelope and recorded in entity `history[]`.
  - **Reset and restore:** `env.reset` enforces `reset_scope: app_instance`, returning only this ShelfMark instance to its loaded baseline seed and advancing `epoch` without touching Mail or any other App.
- **Events and notifications (required):**
  - **Accepted Infra events** (task scenarios choose timing and payload; queue order is seeded and advanced explicitly by events):
    - `hold.ready_for_pickup`: transitions a matching `queued` hold to `ready_for_pickup` and sets `pickup_expires_at`. Matches by `hold_id` OR by composite key `{title_id, card_id, pickup_branch_id}` (earliest active `queued` hold, enabling tasks to advance holds placed during a run). If no active `queued` hold matches (or the hold was cancelled), rejects with `invalid_event` leaving state unchanged. Example: `{"event_id": "evt-lib-001", "at": "2026-11-18T10:00:00+00:00", "operation": "hold.ready_for_pickup", "payload": {"hold_id": "hld-402", "title_id": "ttl-901", "card_id": "card-maya", "pickup_branch_id": "br-westside", "pickup_expires_at": "2026-11-21T17:00:00+00:00"}}`.
    - `hold.checked_out`: records offline physical pickup, transitioning a `ready_for_pickup` hold (matched by `hold_id` or `{title_id, card_id}`) to `checked_out` and creating an `active` loan with `due_at`. Example: `{"event_id": "evt-lib-002", "at": "2026-11-19T14:00:00+00:00", "operation": "hold.checked_out", "payload": {"hold_id": "hld-402", "loan_id": "ln-402", "due_at": "2026-12-10T23:59:59+00:00"}}`.
    - `loan.returned`: records offline physical return, transitioning an `active` or `overdue` loan to `returned`. Example: `{"event_id": "evt-lib-003", "at": "2026-11-19T15:30:00+00:00", "operation": "loan.returned", "payload": {"loan_id": "ln-310", "branch_id": "br-westside", "note": "Checked in at Westside drop box"}}`.
    - `loan.queue_pressure`: updates waiting hold count on a title (`queued_patrons`), blocking renewals when `> 0`. Example: `{"event_id": "evt-lib-004", "at": "2026-11-19T08:00:00+00:00", "operation": "loan.queue_pressure", "payload": {"title_id": "ttl-901", "queued_patrons": 2}}`.
    - `fine.assess`: posts an overdue or damaged-item fee and updates `card_status` to `blocked_fines` if total open fines reach `block_threshold_cents`. Example: `{"event_id": "evt-lib-005", "at": "2026-11-19T12:00:00+00:00", "operation": "fine.assess", "payload": {"card_id": "card-maya-kid", "fine_id": "fin-77", "loan_id": "ln-310", "amount_cents": 1200, "reason": "overdue_12_days"}}`.
    - `fine.dispute_decided`: records the library's decision on a `disputed` fine (`waived` or `open` if denied) and recomputes `card_status` (`blocked_fines -> active` if open balance drops below `block_threshold_cents`). Example: `{"event_id": "evt-lib-006", "at": "2026-11-20T11:00:00+00:00", "operation": "fine.dispute_decided", "payload": {"fine_id": "fin-77", "decision": "waived", "note": "Drop-box return confirmed on 2026-11-19"}}`.
    - `branch.closure`: closes a branch for a virtual-time window, extending `pickup_expires_at` once per affected `ready_for_pickup` hold at that branch and cancelling affected study-room bookings without late-cancellation penalty. Example: `{"event_id": "evt-lib-007", "at": "2026-11-20T07:00:00+00:00", "operation": "branch.closure", "payload": {"branch_id": "br-westside", "closed_until": "2026-11-22T09:00:00+00:00", "reason": "HVAC maintenance"}}`.
    - `room_booking.no_show`: records an offline missed study-room reservation, transitioning a `confirmed` booking to `no_show`. Example: `{"event_id": "evt-lib-008", "at": "2026-11-20T16:15:00+00:00", "operation": "room_booking.no_show", "payload": {"booking_id": "rm-201", "note": "Room unoccupied 15 minutes past start"}}`.
  - **Virtual-time business rules:** Pickup expiration (`virtual_now > pickup_expires_at`), hold suspension auto-resume (`virtual_now >= resume_at`), loan overdue (`virtual_now > due_at`), and study-room free-cancellation cutoffs (`virtual_now <= free_cancel_cutoff_at`) evaluate strictly against Core's `ctx.virtual_now` on reads (deriving `effective_status` without mutating state) and commit on the next write or event. `env.advance_time` alone performs no mutations and sends no emails.
  - **Messaging directions & explicit post-commit publisher:** `publishes`: `channel.email` (send-only, CloudEvents 1.0 wire envelope matching `urn:pale:email-message:2` / `urn:pale:email-payload:1` / `org.pale.mail.notification.v1` -> Mail `mail.receive_notification`, using an unchanged copy of Mail's `router-message.schema.json`). `receives`: `None`. Outbound notices are invoked explicitly after commit via `src/publisher.cjs`, carrying the event/commit timestamp and unique CloudEvents `id` (`<= 100` chars), verified via `mail.get` (`thread_id === wire.id`) through `runtime/messaging/service.cjs`. Delivery rejection leaves local ShelfMark state committed and Mail unchanged; unknown acknowledgements return `{stage: "unknown_outcome", stop_run: true}`. Wire-message payload example (matches `examples/apps/mail/schemas/email-payload.schema.json`, `asset_ids: []`, `extensions: []`):
    `{"channel": "channel.email", "recipient": {"kind": "person_ref", "id": "person-maya"}, "source_object": {"app_id": "shelfmark-library", "account_id": "acct-maya", "object_type": "hold", "object_id": "hld-402"}, "content": {"title": "ShelfMark Hold Ready at Westside Branch", "body": {"format": "text/plain", "text": "Your hold hld-402 is ready for pickup until 2026-11-21T17:00:00+00:00."}, "asset_ids": []}, "extensions": []}`.
- **Shared data and dependencies (required):**
  - Patrons and household members are referenced by shared IDs (`person_ref`, `account_id`) via `fixtures/binding.json`; ShelfMark uses a single bound parent account with seed-declared `managed_cards[]` and does not duplicate Contacts or Mail accounts.
  - Assets and media fit PALE's reference profile: original synthetic PNG book-cover/branch-map cards and 1 UI icon plus 1 explicit missing-asset fixture, at most 8 bundled assets and <= 50 KiB total decoded bytes. Missing optional assets return a structured `ASSET_MISSING` warning on read.
  - Standalone package boundary: `apps/shelfmark-library/` runs independently using only Node 18+, pinned Core API `1.2.0` / public runtime `1.6.0`, and its own package files. `examples/apps/mail` (`v1.3.0`) is exercised in `examples/mail-integration.cjs` via `runtime/messaging/service.cjs`.
