## 2. What you plan to build

**✍️ Your answer (required):** A resettable app in which an agent can maintain sourced driver/vehicle facts, configure desired coverage, obtain written quotes from multiple fictional insurers, respond to information requests, revise or withdraw applications, inspect quote versions/expiry and save a source-linked comparison. The environment records what was requested, which profile version was disclosed, and what each provider actually offered. It does not select the best policy, infer the user's risk preferences or label a quote as meeting hidden task criteria.

Initial workflows:

1. **Sourced profile and requested coverage.** Inspect/edit synthetic drivers, vehicle, garaging location, mileage/use, current declarations and requested effective date. Fields carry source/time and confirmed/unknown status. Configure coverage types/limits, deductibles, optional benefits and payment preference. Save immutable profile/coverage versions. An unknown answer remains unknown; the app never invents a license/claims history or an eligibility fact.
2. **Provider-specific application and consent.** Inspect each insurer's required fields and disclosure destinations; preview the exact application payload and requested coverage; submit under current scoped authority, amend/resubmit or withdraw. An insurer can request missing information or decline a quote with a public reason. The agent cannot assert a user answer merely because it lowers the premium. Preserve what was actually disclosed and when; a later edit cannot undo an earlier disclosure.
3. **Written quote and revision lifecycle.** Retrieve a quoted offer containing provider/legal-entity ID, application/profile version, actual offered coverage, limits/deductibles, exclusions or unresolved fields, effective date, term, premium, fees, installment schedule, discount conditions and expiry. A provider can return a different default from the requested configuration; that difference is visible. Revisions supersede prior quote versions without erasing them. A new profile or coverage version does not magically refresh already issued offers.
4. **Requote and collection management.** Request a revised configuration, answer an actual information request from obtained facts, track pending responses and expired/withdrawn offers, and archive superseded comparisons. Show explicit versions and dependencies rather than an overall agent-facing 'correct comparison' result. A published expiry or response deadline is visible; private provider event schedules are not.
5. **Comparison artifact.** Add/remove actual quote versions in a saved collection, attach the agent's sourced comparison notes and export the selected raw quote terms and comparison artifact. The app supplies exact provider totals and underlying fee schedules, not a task-specific recommendation/ranking. The agent decides how to normalize periods/costs, which offers satisfy the user and what uncertainties to explain. A quote is an estimate/offer under its stated conditions; no policy is bound by exporting or selecting it.

Illustrative downstream task: compare renewal alternatives while retaining a user's existing important coverages and deductible ceiling. One offer omits a requested coverage, one uses a higher deductible or conditional discount, and a later mileage update makes earlier offers outdated. The agent must obtain current, comparable quotes and explain any remaining differences. The companion Task proposal defines that person's history, changes, rubric and model trials separately.

**Independent scope:** [Finance #6](https://github.com/MatrAIx-ai/Personal-Agents-Last-Exam/pull/6) provides account/transaction operations; [document records #33](https://github.com/MatrAIx-ai/Personal-Agents-Last-Exam/pull/33) mentions insurance-document comparison; [patient portal #14](https://github.com/MatrAIx-ai/Personal-Agents-Last-Exam/pull/14) covers medical billing and a possible benefits connection. Coverline adds provider-specific applications, consented disclosures, information requests and written auto-quote version lifecycles. It has separate business state and reset/validation evidence. Existing policy documents and the word 'insurance' in other proposals are acknowledged adjacent scope.

## 3. Potential app connections

- **Internal personal apps (required):** Files for synthetic current declarations, application evidence and written quotes; Mail for insurer information requests, quote-ready and expiry notices. Calendar can supply a user-granted renewal/reminder date if supported. Local fixtures provide equivalent records for business tests. Reading a document does not itself authorize sharing its contents with every provider.
- **Other apps and websites (required):** Four local fictional insurer endpoints with deterministic quote/rule fixtures. They can return known public defaults and require missing fields. No live insurer, comparison broker, motor-record, credit-check or underwriting service. Finance #6 can optionally provide authorized affordability context; it does not choose coverage or receive automatic payments.

### Integration details

- **Operations and access (required):** Browser GUI and same-state MCP/API for profile/coverage reads and edits, provider requirements, payload/consent previews, application submission/amendment/withdrawal, information-response actions, quote retrieval/requote and comparison export. Platform-only operations load/reset/restore state, advance time and deliver provider replies/updates. Disclosure and submission must use current authority scoped to provider, fields and purpose. Exact method names and adopted consent/actor interfaces are agreed at M0.
- **State and lifecycle (required):** Versioned provider/coverage/rule definitions; owner-scoped profile, documents and consent references; per-run applications, immutable payload snapshots, information requests, quote versions, comparison/export artifacts and event cursors. States include draft/submitted/needs-information/quoted/declined/withdrawn/expired as applicable. Exact cents/currency and explicit terms/instants. Request IDs return original results; conflicting/stale writes fail without partial disclosure or another application. Reset clears all mutable state, disclosures and deliveries; restore resumes the same recorded run.
- **Events and notifications (required):** Provider information request, quote/revised-quote delivery, expiry, rule publication and user-source correction. Example: a user's confirmed mileage update creates profile version 2 while a quote still references version 1; the app exposes both, leaving the agent to decide which requotes/comparison changes are needed. Responses bind actual application IDs and versions. Mail notices carry the affected references; tasks determine timing and permitted observations. No hidden desired provider, optimum or private rating/event schedule enters agent observations.
- **Shared data and dependencies (required):** Person/vehicle/provider, source-document, profile/coverage version, disclosure, application/revision, information request, quote/version and export IDs. Structured quote terms plus original UTF-8/PDF-style synthetic documents with hash/source/time references. Unknown, excluded, not-offered and zero-cost fields are distinguishable. Local insurer fixtures work independently; official Mail/Files/Calendar and host permission/event/lifecycle contracts remain design dependencies. Adapters translate actual schemas and do not decide comparability or the user's preferred trade-off.
