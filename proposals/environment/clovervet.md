## 2. What you plan to build

**✍️ Your answer (required):** CloverVet is a resettable, independently branded veterinary care, vaccination-compliance, boarding/travel clearance and prescription-refill simulator where a booking or refill can succeed on the surface and still violate a household's or pet's real constraints. Real pet care involves multi-pet households with distinct species, weight bands, food/drug allergies, fear-free handling needs, delegated pet-sitter permissions, vaccination waiting periods (e.g., 7-day Bordetella buffer before boarding or 14-day primary Rabies waiting window), annual heartworm-test prerequisites for preventative refills, pre-anesthetic bloodwork windows for dental procedures, and strict 10-day validity windows for interstate travel health certificates. A personal agent must check exact pet-specific clinical history, household travel dates, allergy flags and virtual-time compliance windows rather than booking the earliest slot or refilling the last order blindly.

Core reusable workflows (entities, state transitions, reads/writes, and failure/control paths):

1. **Manage household pet profiles, allergies and delegated caretakers (`pet_profile`: `active -> transferred | deceased`):**
   - *Reads/writes:* list or inspect household pets (species, breed, `weight_kg`, microchip ID, allergy tags such as `beef_protein` or `sulfa_drugs`, handling preferences such as `fear_free_room` or `cat_only_slot`, annual exam and lab validity dates, and `authorized_caretakers[]` with scoped permissions `pickup_only | routine_visits | emergency_cap_cents`); update mutable household contact/handling notes or caretaker delegations.
   - *Failure/control:* querying an unknown pet ID returns `not_found`; delegating an unbound `person_ref` returns `validation_error`; editing a `deceased` or `transferred` pet returns `invalid_state_transition`; stale `expected_version` returns Core `stale_version`.
2. **Track vaccinations, lab prerequisites and boarding/travel health clearances (`vaccination_record` & `clearance_certificate`: `draft -> issued -> expired | revoked`):**
   - *Reads/writes:* list vaccination records and lab clearances (e.g., annual heartworm antigen test, pre-anesthetic blood panel); run deterministic compliance checks (`clovervet.clearance.check`) for a target `boarding_stay` (`check_in_at` to `check_out_at`) or `interstate_travel` (`departure_at`), checking expiry through the entire stay, post-vaccination waiting periods, and exam recency; issue or revoke a clearance certificate when all prerequisites pass, optionally attaching a structured external requirement reference (`requirement_ref: {kind: "file_ref" | "asset_ref", id, version?}`).
   - *Failure/control:* requesting a certificate when a vaccine expires mid-stay returns `VACCINE_EXPIRES_BEFORE_END`; requesting inside the post-vaccination waiting period returns `WAITING_PERIOD_UNMET`; requesting an interstate certificate more than 10 days before departure returns `CERTIFICATE_WINDOW_EXCEEDED`; malformed `requirement_ref` returns `REFERENCE_INVALID`.
3. **Search clinic slots and book, reschedule or cancel veterinary appointments (`appointment`: `scheduled -> checked_in -> completed | rescheduled | cancelled | no_show`):**
   - *Reads/writes:* search available slots by clinic branch, veterinarian, visit type (`wellness_exam`, `vaccine_booster`, `sick_visit`, `dental_cleaning`, `travel_certificate_exam`, `urgent_triage`) and handling capability (`fear_free_room`, `cat_only_slot`); book, reschedule or cancel appointments with explicit confirmation codes and optional `authorized_caretaker_ref`.
   - *Failure/control:* booking a `dental_cleaning` without a valid blood panel within 30 days returns `LAB_PREREQUISITE_MISSING`; booking a `fear_free_room`-required pet into a standard slot returns `HANDLING_CONSTRAINT_MISMATCH`; double-booking a vet or pet returns `SLOT_CONFLICT`; cancelling strictly inside the 24-hour late-cancel window (`starts_at - virtual_now < 24h`) records a deterministic late-cancellation fee unless an Infra `clinic.schedule_disruption` event opened a penalty-free window; cancelling a `completed` or `cancelled` visit returns `invalid_state_transition`.
4. **Manage veterinary prescriptions and therapeutic-diet refills (`prescription_refill`: `requested -> vet_review -> approved_pickup | approved_delivery | denied | cancelled`):**
   - *Reads/writes:* list active prescriptions (medication/diet name, dosage weight band, flavor/allergen tags, remaining refills, heartworm-test prerequisite flag, expiry date); submit a refill request specifying fulfillment mode (`clinic_pickup` or `home_delivery`), shipping address or authorized pickup caretaker; amend fulfillment/address/pickup details while `requested` or `vet_review`; or cancel a pending refill before fulfillment.
   - *Failure/control:* requesting a heartworm preventative refill when `heartworm_test_valid_until < virtual_now` returns `HEARTWORM_TEST_OVERDUE`; requesting a formulation whose allergen tags intersect the pet's `allergies[]` (e.g., `beef_protein` chewable for a beef-allergic dog) returns `ALLERGEN_CONFLICT`; requesting with `refills_remaining === 0` or expired prescription returns `NO_REFILLS_REMAINING` / `PRESCRIPTION_EXPIRED`; requesting a second active refill for the same prescription returns `DUPLICATE_ACTIVE_REFILL`; amending or cancelling an `approved_*`, `denied`, or `cancelled` refill returns `invalid_state_transition`.

Reuse across distinct task situations: (a) a household preparing for a 6-day holiday trip must verify boarding clearance for two pets, discover that one dog's Bordetella expires on day 3 of the stay and needs a booster at least 7 days prior, book a fear-free vaccine slot, and delegate pickup to a neighbor; (b) an owner reordering heartworm and allergy medications must catch that the dog's weight band changed, the annual heartworm test is overdue, and the default beef-flavored chew conflicts with a recorded `beef_protein` allergy; (c) a caregiver arranging an interstate flight must schedule a travel-certificate exam inside the 10-day pre-departure window, handle a clinic disruption reschedule without penalty, and amend a pending prescription delivery address after travel plans shift. Every task seeds its own clinics, pets, vaccination/lab history, slots and prescriptions cleanly.

### Integration details

- **Operations and access (required):**
  - **Agent-facing business operations** (all prefixed with `clovervet.` per runtime registration rules; exposed via `agent-mcp` stdio tools and the App-owned Web GUI backed by the same authoritative state; every write requires `expected_version` and `request_id`):
    - `clovervet.pet.list` / `clovervet.pet.get` (`MCP` + `GUI`, `read`): list or inspect household pets, allergies, handling rules, lab validity dates and caretaker delegations.
    - `clovervet.pet.update` (`MCP` + `GUI`, `write`): update mutable handling notes, weight record or delegated `authorized_caretakers[]`.
    - `clovervet.vaccination.list` (`MCP` + `GUI`, `read`): list vaccination records and lab clearances for a pet or household.
    - `clovervet.clearance.check` (`MCP` + `GUI`, `read`): deterministically evaluate boarding or interstate-travel compliance against virtual time and optional `requirement_ref` without mutating state.
    - `clovervet.clearance.issue` / `clovervet.clearance.revoke` (`MCP` + `GUI`, `write`): issue a validated boarding/travel clearance certificate (returning App-owned `certificate_id`) or revoke an existing certificate.
    - `clovervet.slot.search` (`MCP` + `GUI`, `read`): search open clinic slots by branch, vet, visit type, date window and handling capability (`fear_free_room`, `cat_only_slot`).
    - `clovervet.appointment.list` / `clovervet.appointment.get` (`MCP` + `GUI`, `read`): list or inspect appointments and revision history.
    - `clovervet.appointment.book` / `clovervet.appointment.reschedule` / `clovervet.appointment.cancel` (`MCP` + `GUI`, `write`): full appointment lifecycle with prerequisite, handling-flag, conflict and 24-hour late-cancel checks.
    - `clovervet.prescription.list` / `clovervet.prescription.get` (`MCP` + `GUI`, `read`): list or inspect active prescriptions and refill requests.
    - `clovervet.prescription.request_refill` / `clovervet.prescription.amend_refill` / `clovervet.prescription.cancel_refill` (`MCP` + `GUI`, `write`): submit a refill request (enforcing heartworm-test, allergen, refill-count and duplicate-active guards), amend fulfillment/address/pickup details while `requested` or `vet_review`, or cancel before approval.
  - **Infra-only privileged operations** (strictly on `infra-mcp`, unavailable to the Agent and absent from the Agent Web GUI): `env.load_seed`, `env.apply_event`, `env.reset`, `env.snapshot`, `env.event_status`, `env.validate_bundle`, `env.advance_time`.
  - **Reviewer console:** None inside the Agent GUI; inspection uses Core's administrative snapshot/audit interface and standalone reviewer renderer (`gui/src/view.js`).
- **State and lifecycle (required):**
  - **State separation:** Clinic catalog state (`branches[]`, `vets[]`, `slots[]`, `formulations[]`), account-level household state (`account_id`, `owner_person_id`, `pets[]`, `vaccinations[]`, `lab_results[]`, `clearances[]`, `appointments[]`, `prescriptions[]`, `refill_requests[]`), and run-level Core isolation (`run_id`, `app_id`, virtual clock, receipts and audit log). Each task loads its own initial seed via `env.load_seed` against `schemas/seed.schema.json`.
  - **Commit evidence, retries and concurrency:** All writes use Core's native `{status: "committed", app_id: "clovervet", version: {epoch, revision}}` envelope and Core's optimistic concurrency error (`stale_version`). Same-`request_id` retries return Core `duplicate: true` without mutating state; same `request_id` with changed arguments returns Core `idempotency_conflict`. App-owned business confirmation fields (`confirmation_code`, `certificate_id`, `refill_receipt_id`) are returned alongside the Core envelope and recorded in entity `history[]`. Reads never mutate business state; rejected writes preserve business state and record a denial row in Core `state.audit`.
  - **Reset and restore:** `env.reset` enforces `reset_scope: app_instance`, returning only this CloverVet instance to its loaded baseline seed and advancing `epoch` without touching Mail or any other App. Snapshots are inspection evidence, not a cross-App rollback mechanism; notifications already committed in Mail are not undone on local reset.
- **Events and notifications (required):**
  - **Accepted Infra events** (task scenarios choose timing and payload; CloverVet defines deterministic business effects):
    - `vet.vaccination_logged`: records an administered vaccine dose (`vaccine_type`, `administered_at`, `expires_at`, `waiting_period_days`, `lot_number`) for a pet. Example: `{"event_id": "evt-cv-001", "at": "2026-11-18T15:00:00+00:00", "operation": "vet.vaccination_logged", "payload": {"pet_id": "pet-mochi", "vaccine_type": "bordetella", "administered_at": "2026-11-18T14:45:00+00:00", "expires_at": "2027-11-18T23:59:59+00:00", "waiting_period_days": 7, "clinic_branch_id": "br-oakwood"}}`.
    - `vet.lab_result_posted`: records a lab panel result (`heartworm_antigen` or `pre_anesthetic_bloodwork`, `status: negative | positive | cleared | abnormal`, `valid_until`) updating prescription/dental eligibility. Example: `{"event_id": "evt-cv-002", "at": "2026-11-19T11:00:00+00:00", "operation": "vet.lab_result_posted", "payload": {"pet_id": "pet-mochi", "panel_type": "heartworm_antigen", "status": "negative", "valid_until": "2027-11-19T23:59:59+00:00", "note": "Annual snap test negative"}}`.
    - `prescription.decision`: transitions a `requested` or `vet_review` refill to `approved_pickup`, `approved_delivery`, or `denied`, decrementing `refills_remaining` on approval. Example: `{"event_id": "evt-cv-003", "at": "2026-11-19T16:30:00+00:00", "operation": "prescription.decision", "payload": {"refill_id": "rfl-101", "decision": "approved_pickup", "note": "Ready at Oakwood pharmacy counter"}}`.
    - `clinic.schedule_disruption`: marks a clinic branch or vet slot range disrupted, opening a penalty-free reschedule/cancel window (`penalty_free_until`) for affected `scheduled` appointments. Example: `{"event_id": "evt-cv-004", "at": "2026-11-20T08:00:00+00:00", "operation": "clinic.schedule_disruption", "payload": {"branch_id": "br-oakwood", "vet_id": "vet-lin", "affected_from": "2026-11-20T09:00:00+00:00", "affected_until": "2026-11-20T17:00:00+00:00", "penalty_free_until": "2026-11-22T23:59:59+00:00", "reason": "Emergency surgery block"}}`.
  - **Virtual-time business rules:** All vaccine expirations (`expires_at >= stay_end_at` inclusive), post-vaccination waiting periods (`check_in_at >= administered_at + waiting_period_days * 86400s` inclusive), 10-day interstate certificate issuance windows (`0 <= departure_at - virtual_now <= 10d`), lab validity (`valid_until >= virtual_now`), and 24-hour late-cancellation cutoffs (`starts_at - virtual_now < 24h` strictly less) evaluate strictly against Core's supplied `virtual_now` (`env.advance_time` / event `at`), never host wall-clock time. Advancing `virtual_now` alone never dispatches notifications or mutates business records.
  - **Messaging directions & explicit post-commit publisher:** `publishes`: `channel.email` (send-only, CloudEvents 1.0 wire envelope matching `urn:pale:email-message:2` / `urn:pale:email-payload:1` / `org.pale.mail.notification.v1` -> Mail `mail.receive_notification`). `receives`: `None`. Neither local commits nor clock advances emit Mail automatically; an explicit App-owned post-commit publisher (`src/publisher.cjs`, `publishAppointmentConfirmation` and `publishClearanceNotice`) reads the committed record, constructs a deterministic CloudEvents 1.0 envelope (`id: clovervet-<object_type>-<object_id>-<status>`), invokes `router.publish`, and returns a sender-side `correlation` record (`{message_id, event_id, source_object, recipient, router_status}`). Unknown router acknowledgements return `{stage: "unknown_outcome", stop_run: true}` (matching Messaging's stop-and-inspect behavior); rejected deliveries leave local CloverVet state committed and Mail unchanged. Acceptance tests verify Mail via `mail.get` (subject/body/ID) and join `source_object` through the sender-side `correlation` record rather than expecting a new Mail field. Wire-message payload example (matches `examples/apps/mail/schemas/email-payload.schema.json`, `asset_ids: []`, `extensions: []`):
    `{"channel": "channel.email", "recipient": {"kind": "person_ref", "id": "person-hannah"}, "source_object": {"app_id": "clovervet", "account_id": "acct-hannah", "object_type": "appointment", "object_id": "appt-201"}, "content": {"title": "CloverVet Appointment Confirmed: Wellness Exam for Mochi", "body": {"format": "text/plain", "text": "Appointment appt-201 is confirmed for Mochi at Oakwood Clinic (Fear-Free Room 2) on 2026-11-21T10:00:00+00:00."}, "asset_ids": []}, "extensions": []}`.
- **Shared data and dependencies (required):**
  - Household members and delegated caretakers are referenced by shared IDs (`person_ref`, `account_id`) via `fixtures/binding.json`; CloverVet never duplicates Contacts or Mail account stores.
  - Optional external document references (`requirement_ref` on `clearance.check`/`clearance.issue`) use `{kind: "file_ref" | "asset_ref", id, version?}`, validated structurally (ID pattern + optional positive integer `version`) with explicit valid vs `REFERENCE_INVALID` outcomes; CloverVet never imports Files or performs OCR.
  - Assets and media fit PALE's reference profile: original programmatically generated synthetic PNG clinic/vaccine-card diagrams and 1 UI icon plus 1 explicit missing optional asset fixture, at most 8 bundled assets and <= 50 KiB total decoded bytes (well within the 64-asset / 1 MiB ceiling). Missing optional assets return a structured `ASSET_MISSING` warning on read rather than throwing.
  - Standalone package boundary: `apps/clovervet/` runs independently using only Node 18+, pinned Core API `1.2.0` / public runtime `1.6.0`, and its own package files. `examples/apps/mail` (`v1.3.0`) is an optional integration target exercised in `examples/mail-integration.cjs` via `runtime/messaging/service.cjs`.
