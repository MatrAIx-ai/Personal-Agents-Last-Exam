## 2. What you plan to build

**✍️ Your answer (required):** NYC 311 Watch is a local service-request tracker for public street-condition cases. A resident or their agent can (1) find and read a case by local ID or filter by borough and visible status, (2) preview, confirm, edit or remove a private watch, and (3) read local activity and acknowledge reminders triggered by a relevant new status. For example, a resident coordinating recurring care visits wants notice only when the agency closes a watched case or a scenario event reopens it, not when it changes agency or receives an administrative update. The agent must honor which cases and changes the resident chose, distinguish current from stale information and avoid duplicate reminders. Borough is context only; the App does not infer routing or whether a street is safe.

### Integration details

- **Operations and access (required):** Reuse the [public Core and Web Host](../../runtime/README.md) on a pinned compatible revision (initial target: runtime 1.6.0 / Core API 1.2.0). App-owned Lookup, Case and Watch/Activity views use the same Agent MCP connection and account state as direct tools. Reads: `civic311.search_cases`, `civic311.read_case`, `civic311.list_watches`, `civic311.list_activity`. `read_case` returns the local `case_id`, `created_at`, borough, problem category, current agency (nullable), latest synthetic administrative update code (nullable), `status`, and `last_updated_at` (nullable). Known case statuses are `open`, `in_progress`, and `closed`; `unknown` is a read-only sentinel for missing as-of evidence, never an accepted event status. `last_updated_at` is the time of the most recent visible case observation or applied scenario event, not the time it was read. Writes: `civic311.save_watch`, `civic311.remove_watch`, `civic311.ack_activity`. Preview may remain in the browser; confirm performs the versioned write, discard does not write. Infra alone uses `env.load_seed`, `env.snapshot`, `env.advance_time`, `env.apply_event` and `env.reset`.
- **State and lifecycle (required):** Core owns the public case snapshot, synthetic account's watches and local activity in each isolated run; no private datastore. One account cannot list or change another account's watches. Require caller's expected version and a stable request ID on writes; retries of identical requests return the original receipt, and conflicting or stale writes do not mutate state. Each watch stores `watch_id`, its owner account, one `case_id`, a nonempty set of selected `change_types`, and its version. Allowed selections are `resolved`, `reopened`, `agency_changed`, and `admin_update`; `save_watch` exposes those choices, and the UI and `list_watches` show the saved selections. Reset restores the selected seed, clock, watch state and receipts. Historical source snapshots and simulated status events are distinct. A case is not visible before its represented creation time. Before its first supported observation, `read_case` returns `unknown` for status and null for agency, administrative update code and `last_updated_at`, rather than inferring that it was open or exposing later snapshot fields. At or after the observation, apply only the visible observations and scenario events in virtual-time order, preserving fields untouched by each event. No future events are preloaded as visible outcomes.
- **Events and notifications (required):** Tasks inject versioned local scenario events. Example envelope: `{"event_id":"scenario-case-17-change","at":"2027-01-10T09:00:00-05:00","operation":"civic311.case_status_changed","payload":{"case_id":"C17","previous_status":"open","new_status":"closed"}}`. `open` or `in_progress` → `closed` maps to `resolved` (agency closure, not proof of physical repair); `closed` → `open` or `in_progress` maps to `reopened`; `open` ↔ `in_progress` updates the case but has no selectable change type. `civic311.case_agency_changed` (`case_id`, `previous_agency`, `new_agency`) maps to `agency_changed` and updates the current agency without changing status. `civic311.case_admin_updated` (`case_id`, `update_code`, limited to synthetic codes `inspection_logged` or `record_corrected`) maps to `admin_update`, recording the code in case state without changing status or agency. All three event types use the same envelope and update `last_updated_at` on a valid change. A watch matches only if the active watch's `case_id` equals the event case and the derived change type is selected. Append one local activity item per matching watch/event pair, referencing the watch, case, event and change type; the closure message says the agency closed the case. A valid event with no matching watch still updates the case but creates no activity. No outbound notification is sent. Duplicate event IDs are idempotent; unknown cases, mismatched prior state, no-op transitions, denied callers, and invalid or stale event timestamps do not mutate state. Status labels are a documented sandbox mapping, not municipal guarantees.
- **Shared data and dependencies (required):** Use stable dataset-local case IDs and synthetic accounts. Allowlisted record fields: represented creation date, borough, case category and agency; use recorded closure date only when available and status only with a known snapshot time. Omit street addresses, coordinates, original ticket lookup identifiers, names, contacts, free text and media from released fixtures. Build-time queries select only reviewed columns; use the upstream unique key transiently for deduplication. Only Node built-ins and the shared runtime are needed to run the App.
