# QuestShelf multimodal game library and recommendation hub

**Proposed PR title** — `[Environment Proposal] [Games & play + Social & communities] QuestShelf multimodal game library and recommendation hub`

## 1. App and domains

- **Authors / GitHub handles (required):** @shangliy
- **Reference app or website / URL (required):** QuestShelf is an independently branded synthetic cross-platform game library, playtime tracker, and constraint-aware game recommender. [Backloggd](https://www.backloggd.com/) and [HowLongToBeat](https://howlongtobeat.com/) are public references for cross-platform shelves (played/playing/backlog/dropped), completion-time estimates, friend co-op lists, and negative-feedback filtering.
- **Primary domain (required):** Games & play
- **Secondary domains (optional):** Social & communities

## 2. What you plan to build

**✍️ Your answer (required):** QuestShelf lets a personal agent search a user's cross-platform game library (PC, console, handheld) and broader catalog, inspect both structured metadata (playtime estimates, platform ownership, cross-play support, offline mode, accessibility flags) and synthetic visual cover/HUD preview cards delivered as MCP resources (`pale://<run>/questshelf/assets/<asset_id>`, showing camera perspective, visual darkness/horror cues, and handheld UI text readability), learn from explicit negative feedback (`dropped` reasons such as motion sickness, grind fatigue, tiny UI text, or horror triggers, plus `muted_tags` and `not_interested` dismissals), and coordinate group game-night shortlists with friends.

### Three example requests

| User request | What the user and agent encounter | What a reviewer can check |
| --- | --- | --- |
| **Multi-constraint weekend recommendation.** “Pick a game from my backlog I can finish this weekend on my handheld during a flight — no first-person games and nothing scary.” | The user owns 14 backlog titles. The highest-rated handheld title is a 45-hour RPG (`game-iron-sovereign`, exceeds a 6–8 hour weekend budget). A 5-hour indie title (`game-lantern-hollow`) deliberately has incomplete text tags (`["indie", "atmospheric", "story"]`), but its attached gameplay/HUD preview PNG (read via MCP `resources/read`) clearly depicts a dark 62° FOV first-person corridor with horror UI cues, matching the user's logged `dropped` reasons (`first_person_motion_sickness`, `horror`). A 6-hour isometric puzzle-adventure (`game-clockwork-isle`) works offline, has large 16pt handheld-readable HUD text in its preview image, and fits the user's preferences. | The agent filters by owned handheld + offline + `<= 8h` main story, reads MCP image resources to catch the unlabeled first-person horror title (whose visual cues are never leaked into `questshelf.recommend.rank`), respects the user's dropped-history preferences, and recommends `game-clockwork-isle` without altering library status unless asked. |
| **Cross-play friend co-op matching.** “Find two games Alex and I both own that support cross-play for a 90-minute session tonight, and create or update our Friday poll with them.” | The user owns games on PC and Switch; Alex's shared QuestShelf friend record (`friend-alex`) lists only PS5 titles. Only two overlapping games (`game-orbit-relay`, `game-ember-kitchen`) support PC–PS5 cross-play with `<= 90 min` session length; a third overlapping candidate (`game-boulder-league`) lacks PC–PS5 cross-play, and a fourth (`game-neon-drift-99`) is in the user's `not_interested` / `muted_tags` list. | The agent cross-checks platform ownership and cross-play matrices, excludes the muted and non-cross-play titles, calls `questshelf.poll.create` (or `questshelf.poll.update` if an open poll already exists) with exactly the two valid games and `invited_friend_ids: ["friend-alex"]`, and a prewritten `questshelf.poll.friend_vote` event later reaches that open poll without knowing its runtime `poll_id`. |
| **Negative feedback & shelf update.** “I'm dropping *Ashen Depths* — the tiny font on handheld gives me a headache and it's too grindy. Log that and refresh my top 3 recommendations.” | Logging a `dropped` entry on `game-ashen-depths` with structured `drop_reasons: ["tiny_ui_text", "excessive_grind"]` adds those reasons to the user's active negative-feedback profile. Subsequent calls to `questshelf.recommend.rank` deterministically filter out grind-heavy (`tags` containing `excessive_grind`) and tiny-UI (`tags` containing `tiny_ui_text` or `hud_font_pt < 12`) candidates, replacing `game-iron-sovereign` and `game-frost-protocol` in the Top 3 with readable, non-grindy matches (`game-clockwork-isle`, `game-moss-cartographer`, `game-velvet-cipher`). | Library shelf transitions cleanly from `playing` to `dropped` with timestamped reason codes; re-running `questshelf.recommend.rank` deterministically shifts Top 3 from `[game-iron-sovereign, game-clockwork-isle, game-frost-protocol]` to `[game-clockwork-isle, game-moss-cartographer, game-velvet-cipher]`. |

**Related work.** Steam ([PR #11](https://github.com/MatrAIx-ai/Personal-Agents-Last-Exam/pull/11)) models a single-platform digital storefront (purchasing/refunds); Treefort ([PR #124](https://github.com/MatrAIx-ai/Personal-Agents-Last-Exam/pull/124)) models parental screen-time and purchase controls. Neither covers cross-platform personal game shelves, playtime budgets, negative-feedback/DNF preference tracking, visual HUD/accessibility previews, or friend co-op poll matching. QuestShelf runs completely independently in the underserved `Games & play` domain.

## 3. Potential app connections

- **Internal personal apps (required):** None required for v1. Task scenarios can supply external friend constraints or travel schedules via existing personal apps (`messages`, `calendar`, `notes`) called independently by the agent.
- **Other apps and websites (required):** None at runtime. All games, friend profiles, playtime statistics, and visual preview cards live in self-contained local synthetic fixtures.

### Integration details

- **Operations and access (required):** All Agent-facing MCP tool names carry the `questshelf.` prefix (`runtime 1.6.0` / `core_api_version 1.2.0`):
  1. `questshelf.catalog.search` (read-only) — filter catalog or owned shelves by `query`, `platform`, `owned_only`, `shelf_status`, `genre`, `tag`, `max_hours`, `max_session_minutes`, `offline_ok`, `cross_play_platforms`, `min_coop_players`, `exclude_muted`.
  2. `questshelf.game.get` (read-only) — returns full structured game metadata, playtime breakdown (`main` / `main_extra` / `completionist`), tags, current shelf entry, `asset_ids`, and MCP resource URIs (`pale://<run>/questshelf/assets/<asset_id>`).
  3. **Image delivery via MCP resources:** Preview PNG cards are delivered to the Agent as standard PALE MCP resources (`resources/list` and `resources/read` on `pale://<run>/questshelf/assets/<asset_id>`, audited in Core by `runtime/core/mcp.cjs`). `questshelf.asset.read` (read-only) is additionally exposed for deterministic JSON/SHA-256 verification via `ctx.assets.read` (returning descriptor metadata, SHA-256 digest, and base64 payload), while multimodal visual inspection by Agents uses MCP `resources/read`.
  4. `questshelf.shelf.list` (read-only) & `questshelf.shelf.upsert` (write) — manage `backlog`, `playing`, `completed`, `dropped` entries with `owned_platforms`, `hours_logged`, `rating`, `drop_reasons`, and `note`.
  5. `questshelf.preferences.get` (read-only) & `questshelf.preferences.update` (write) — manage `preferred_platforms`, `muted_tags`, `not_interested` game IDs, `avoid_reasons`, and optional `min_hud_font_pt`.
  6. `questshelf.recommend.rank` (read-only) — deterministic, **structured-fields-only** recommender (never inspects image content or hidden evaluation-only visual cues so Example 1's multimodal trap holds):
     - **Inputs:** `pool` (`"backlog"` | `"catalog"` | `"unplayed"`, default `"unplayed"`), `platform`, `max_hours`, `max_session_minutes`, `offline_ok`, `with_friend_id`, `limit` (default `5`).
     - **Hard filter mappings:** excludes `not_interested` IDs, `dropped`/`completed` entries, any game matching `preferences.muted_tags`, and games violating active `avoid_reasons` (union of `preferences.avoid_reasons` and `drop_reasons` on `dropped` shelves): `first_person_motion_sickness` → excludes `tags` containing `"first_person"`; `horror` → excludes `tags` containing `"horror"`; `excessive_grind` → excludes `tags` containing `"excessive_grind"`; `tiny_ui_text` → excludes `tags` containing `"tiny_ui_text"` or `hud_font_pt < 12`.
     - **Score & tie-break:** `score = round2(critic_rating + min(0.60, 0.20 * |game.tags ∩ liked_completed_tags|) + (0.25 if backlog else 0) + hud_pref_adj)` where `liked_completed_tags` are tags from `completed` games rated `>= 8.0`, and when `preferences.min_hud_font_pt` is non-null, `hud_pref_adj = +0.35` if `hud_font_pt >= min_hud_font_pt` else `-1.20` (`0` when `null`). Ties break by lexicographical ascending `game_id`.
  7. `questshelf.friends.list` (read-only) — lists QuestShelf friend records (`friend_id`, `name`, `platforms`, `owned_games`).
  8. `questshelf.poll.list` (read-only), `questshelf.poll.create` (write), `questshelf.poll.update` (write), `questshelf.poll.vote` (write), `questshelf.poll.close` (write) — manage game-night polls. Each poll stores: `poll_id`, `title`, `status` (`open` | `closed`), `candidate_game_ids`, `invited_friend_ids`, `max_session_minutes`, `closes_at` (ISO 8601 `date-time` or `null`), `votes[]` (`voter_id`, `selected_game_ids`, `note`, `voted_at`), `winner_game_ids`, `created_at`, `closed_at`. At most **one `open` poll per account** is permitted at a time (`questshelf.poll.create` returns `conflict` if an open poll already exists; `questshelf.poll.update` edits `title`, `candidate_game_ids`, `invited_friend_ids`, `max_session_minutes`, or `closes_at` on the open poll and rejects closed polls).
  - **Privileged Infra operations:** standard Core `runtime 1.6.0` administrative tools only — `env.load_seed`, `env.reset`, `env.apply_event`, `env.snapshot`, `env.event_status`, `env.validate_bundle`, and host clock `env.advance_time`.

- **State, account binding, and lifecycle (required):**
  - **Bound user & seeds:** The Agent acts for the bound user whose `person_id` is the `owner_person_id` of the single `questshelf` account declared in `binding.json`. The two curated user shelf histories in §4 are **two separate seed fixtures** (one account per run loaded via `env.load_seed`), not two accounts inside one run.
  - **Friends data:** Friends are QuestShelf App records (`friends[]` inside the seed state) containing each friend's `friend_id`, display `name`, `platforms`, and shared `owned_games` (`[{ game_id, platform }]`); the Agent reads them via `questshelf.friends.list` and Infra updates them by `friend_id` via `questshelf.friend.library_update`.
  - **Concurrency & reset:** All writes are guarded by Core `request_id` idempotency and optimistic `expected_version` (`epoch`/`revision`) checks; voting twice by the same voter updates in place rather than duplicating; invalid shelf transitions, unknown game/friend/poll IDs, or mutating/voting on a closed poll reject atomically without changing state. `env.reset` restores baseline catalog, assets, shelves, preferences, friends, polls, and virtual clock. Historical records span `2026-01-01` onward, and relative temporal queries ("this weekend", "tonight", "Friday") are resolved against `ctx.virtual_now`.

- **Events and notifications (required):** Infra applies three scripted events via `env.apply_event`:
  1. `questshelf.game.update_patch` — updates game metadata (`cross_play_platforms`, `offline_ok`, `hud_font_pt`, `add_tags`, and optional new preview asset added via the `env.apply_event` `bundle`, keeping `resources/list` and `questshelf.game.get` `asset_ids`/`resource_uris` in sync).
  2. `questshelf.friend.library_update` — adds or removes `{ game_id, platform }` on a friend record identified by `friend_id`.
  3. `questshelf.poll.friend_vote` — records a friend's vote on an open game-night poll using deterministic **App-side matching** so prewritten task events reach polls created by the Agent during the run without knowing a runtime-generated `poll_id`:
     - **Matching rule:** `payload.poll_id` is optional. If `payload.poll_id` is provided, QuestShelf looks up that exact poll; if `payload.poll_id` is omitted, QuestShelf locates the account's single `open` poll whose `invited_friend_ids` contains `payload.friend_id`.
     - **Three explicit rejection cases (all fail atomically with `invalid_event` and zero state change):**
       1. *No matching open poll* (no open poll exists for this account, or an explicit `poll_id` is unknown) → `invalid_event`.
       2. *Poll is closed* (`status === "closed"`, or `poll.closes_at` is set and `event.at > poll.closes_at`) → `invalid_event`.
       3. *Friend not invited or invalid game selection* (`friend_id` unknown or not in `poll.invited_friend_ids`, or any entry in `selected_game_ids` is not in `poll.candidate_game_ids`) → `invalid_event`.
     - Replaying an identical `event_id` is deduplicated by Core; reusing an `event_id` with modified content fails with `idempotency_conflict`. QuestShelf sends and receives no cross-app notifications in v1 (polls remain self-contained in v1).

```json
{
  "event_id": "friend-alex-vote-01",
  "at": "2026-11-20T17:15:00-08:00",
  "operation": "questshelf.poll.friend_vote",
  "payload": {
    "friend_id": "friend-alex",
    "selected_game_ids": ["game-orbit-relay"],
    "note": "Only have PS5 tonight and free for 90 mins max."
  }
}
```

- **Shared data and dependencies (required):** Node.js 18+ and public Core runtime (`runtime 1.6.0`, `core_api_version 1.2.0`). Fixtures ship as UTF-8 JSON plus 20–24 synthetic PNG cover & gameplay/HUD preview cards (~110–480 KiB total decoded bytes, strictly within `64-asset / 1 MiB`). The App runs standalone (`ui: "none"`) with only the shared Core runtime and zero external dependencies.
