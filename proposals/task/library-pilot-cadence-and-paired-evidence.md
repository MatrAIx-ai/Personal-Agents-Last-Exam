## 2. User persona and prior history

**✍️ Your answer (required):** Laila coordinates a small adult-learning pilot at the fictional Alder Library. The November 20 `pilot-plan-v2` has a twelve-week window, January 11–April 4, 2027, with six meetings on January 18, February 1, February 15, March 1, March 15 and March 29, each 10:00–11:30 in `America/Phoenix` (`-07:00`). - **F1 — Misusing learner material.** No distributed teaching resource requests real personal letters, and no analysis or outward report uses P07's withdrawn responses or links P18's responses without permission. ### Implementation decisions and external dependencies

- **Implementation owner and review:** Yixuan He owns task records, controller integration, grader, replay scripts and failure analysis. Independent review follows the repository's normal Task reviewer routing. No other contributor or maintainer is assumed to have committed implementation labor.
- **Selected execution design:** Linux Harbor with a contributor-owned external `BaseAgent` integration and a finite task-session controller. The model loop stays outside the actor sandbox so the trusted controller can pause it, apply due events, synchronize every enabled App, and resume the next session with actual conversation/state. The integration uses the shared public stdio MCP contracts and separate Agent/Infra connections; it does not assume that the planned shared LifePack scheduler already exists. Harbor documents [external custom agents](https://docs.harborframework.com/agents/custom-agents); this is a proposed implementation choice, not a tested adapter release. All model families receive equivalent authorized observations and actions. Model credentials stay in the trusted runner's private configuration, never task files.
- **Isolation design:** The actor receives only its authorized user view, workspace and Agent business tools. Private user-script branches, future events, full App snapshots, answer keys and hints remain outside actor mounts and services. The verifier receives authenticated state exports after actor access stops; an agent-written result file is never authoritative. TeX shell access, where applicable, is limited to the working project in the actor container. Required acceptance probes cover attempted Infra calls, parent-directory/private-file reads, future-event access, forged evidence, reset and cross-run isolation.
- **Version and resource plan:** Keep the reviewed public App/runtime source pinned to `6933c430942c64f94874083815829e4a4b20920a`. During implementation bootstrap, Yixuan records the exact working Harbor/adapter revisions, dependency hashes and successfully built OCI image digest in the LifePack manifest; floating dependencies fail the release check. Proposed starting resources are 2 CPUs, 4 GiB RAM, 8 GiB disk and 20 minutes per actor session, with one identical frozen budget per designated model. They are tested against the reference before freeze. A Linux Docker-capable execution host is required; finding Apptainer or a local compiler alone does not establish Harbor support.
